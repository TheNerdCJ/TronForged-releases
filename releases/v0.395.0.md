## v0.395.0 - console updates stopped undoing themselves

**If you have ever seen a console update appear to install and then still report the old
version, this is why.** On any PC with .NET 10 installed - which is most of them - a console
update rolled itself back automatically before it ever finished starting.

### What was wrong

When a console updates itself, it swaps in the new program and then watches the next couple of
launches to make sure the new build actually starts. If it does not, the old build is put back
automatically - that safety net is deliberate, and it is what stops a bad update from leaving a
machine with a console that will not open.

On a PC with .NET 10, though, one launch of the console is really two programs starting in
sequence, and the safety net was counting both of them. Two counts is the entire budget. So a
perfectly good update spent its whole allowance on the very first launch and put the old build
back, before anything had a chance to confirm it was healthy.

From the outside it looked exactly like the update never happened.

### What changed

The first of those two programs never opens a window - it exists only to start the second one.
It no longer counts as a launch. The safety net is otherwise untouched: a build that genuinely
fails to start is still rolled back after two attempts, and a build that crashes before its
window still gets caught, which is the case the safety net exists for.

### Worth knowing

This was found while investigating something unrelated. Nothing in the product reported it - a
rolled-back update leaves no message, which is why it could persist. If you have consoles that
have been stubbornly refusing to move to a new version, they should now take it.
