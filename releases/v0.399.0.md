## v0.399.0 - the web transport is set up from the Server Console

**Paste the Cloudflare origin certificate and its key, choose a port, press Apply. The server
checks the pair, seals it, and starts the web transport on the spot - nothing is typed into
server.json and the service is not restarted.**

### What was wrong

Turning on the web transport (the door that lets an orange-clouded Cloudflare record carry
remote support, and that gets machines home from hotel and campus networks) meant getting
two PEM files onto the server box by hand, editing three keys in `server.json`, and
restarting the service. A typo in a path left the door silently shut; a wrong key for the
certificate was only discovered when the first device tried it. None of this was checked by
anything before it went live.

### What changed

Server Console > Status now has **Web transport (WSS)...**:

- Two boxes for the certificate and the private key (paste, or **Browse...** to a file), and a
  port box that tells you as you type whether Cloudflare's proxy carries that port
  (443, 2053, 2083, 2087, 2096, 8443).
- **Check** validates without changing anything: the certificate parsed, the key belongs to
  it, the certificate names the shop's advertised address, the port is one the proxy carries.
- **Apply** does the same checks, then seals the pair on the server (in the same protected
  store as the shop's other secrets - the key is never written to a plain file and never
  shown again), starts listening immediately, and on the server box adds the Windows
  Firewall rule for the port. If the port cannot be opened, nothing is changed.
- **Turn off** closes the door but keeps the certificate for next time; **Forget the
  certificate** erases it.
- The Status row says what the door is doing: listening (with the certificate's expiry),
  expiring soon, expired, not a proxy port, certificate does not cover the shop address, or
  off - and what to do next (forward the port on the router; in Cloudflare set the record to
  Proxied and SSL/TLS to Full (strict)).

The server refuses, with a plain sentence, a key that does not belong to the certificate, an
expired or not-yet-valid certificate, a password-protected key, a public key pasted as the
private key, and the server's own sign-in port.

### What stays by hand

Two things only: forwarding the chosen port to the server box on the shop router (same port
both sides), and - once the row is green - flipping the DNS record to Proxied (orange cloud)
and SSL/TLS to Full (strict) in Cloudflare. The setup guide (Part G, step 5) walks through
getting the certificate from Cloudflare: SSL/TLS > Origin Server > Create Certificate, copy
both blocks - the key is shown once.

A server with no console reachable can still use the file route (`wssCert`/`wssKey` paths in
`server.json`); the console route replaces it and moves the pair into the sealed store the
first time Apply is pressed.

### Worth knowing

- The licence is unchanged: the key travels from the Server Console to the shop's own server
  inside the same administrative connection everything else uses, and stays there.
- Nothing in this release has run on real hardware yet; it is proven end to end on loopback
  against the real server and the real console code. The bench plan carries the item.
