# TronForged v0.491.0

Set up, check and retire a domain controller from the Windows Server tool, without signing in to the server.

## Domain controllers

Making a server a domain controller used to mean signing in to it and clicking through about fifteen screens in Server
Manager. Now you can do it from TronForged, at the server or from your fleet during a remote session. It covers Active
Directory Domain Services, with DNS on the new domain controller. DHCP, Exchange and Entra are not part of it.

- **Make this a domain controller.** A Windows Server 2022 or later that is not a domain controller shows this card on its
  Windows Server tab. Choose **Start a new domain** or **Add to an existing domain**. The wizard installs the Active
  Directory role, asks for the domain's name and a recovery password, runs Windows' own checks, promotes the server and
  restarts it. You cannot press Next past a check that found a problem, and each problem is said in plain words.
- **Domain health.** On a domain controller, **Domain health** says in one sentence whether the domain is healthy, and
  names the domain controller and the time if replication has failed. It lists the domain controllers, who holds the five
  master roles, and what Windows' own checks report. It only reads.
- **Demote.** **Demote this domain controller** turns it back into a plain server, after you give the sign-in of a domain
  administrator (user name and password), type the new local Administrator password twice and type the server's name.
- **Passwords are typed once and never stored.** The recovery password, a domain administrator's password and the new
  Administrator password go to the server once and are cleared from the page when sent. They are not written to any log,
  to the audit record, to a file or to the shop server.
- **Windows never restarts by itself.** Promote and Demote finish, say that a restart is needed, and wait. Restart is its
  own step with the server's name typed, so a promotion that worked is never reported as lost. Close the wizard and open
  it later, and it shows where the server really is. While the change is still running it says so and offers no Restart
  (the server refuses one until the change has finished); if TronForged could not confirm the change finished, the
  Restart page says so before you restart.
- **What it refuses, and why.** A server with no fixed IP address (TronForged never changes a server's network settings,
  so set the address first). A domain name ending in .local. Demoting the last domain controller of a domain, or one
  that no other domain controller can stand in for: nothing is forced. Demoting the only global catalog or the only DNS
  server of the domain. A second change while one is already running. Anything else while the server is waiting for a
  restart.
- **Who:** setting up needs the Windows Server privileged permission. Restart and Demote need the Windows Server admin
  permission as well. Domain health needs only the Windows Server read-only permission. Every step is written to the shop
  server's audit log with the server, the action and its outcome (and the domain's names and the domain administrator's
  user name where the step uses them), never a password.
- **Local users and groups on a domain controller:** a domain controller has none, so those actions now say so and point
  to Users and Groups instead of failing in a confusing way.

The server needs the TronForged helper 0.491.0, and your console and the shop server need this version too. With an older
one nothing new appears and nothing else changes.

## Licence and privacy

- The licence gains section 10.14, Domain controllers: who may set one up, restart it or demote it, that TronForged does
  not keep the domain's passwords, never changes a server's network settings and never forces a demotion. Section 10.11
  now lists domain controllers, and section 10.5 says what the shop server's audit log records for these steps.
- The privacy notice (4.1) now says that the shop server's record of a domain controller change includes the domain name
  and the user name of the domain administrator the technician signed in as - never a password.

## Known limits

- Domain controller setup has not been tried yet on real servers. It has been tested with stand-ins for Windows, so the
  exact wording Windows gives for a failed check, and the replication report on a real two-controller domain, are still to
  be confirmed.
- Not in this version: moving or seizing master roles, read-only domain controllers, trusts, child domains and raising
  the domain's functional level.
