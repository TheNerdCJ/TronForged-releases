## v0.417.0 - what needs attention today, and three repairs a shop reported

### The Service Desk opens with what needs attention

The owner's first question on opening the console is whether anything is going wrong, and
until now the answer meant reading the whole list. There is now a card above the ticket
list that says it directly:

- jobs past the time you promised, and jobs promised for today
- jobs waiting on the customer for three or more **working** days
- jobs nothing has happened on for five or more days
- jobs with nobody assigned
- jobs finished but still open
- timers left running for eight or more hours - somebody forgot to stop them
- finished work that is not on an invoice yet, as a total

**Every line names its ticket numbers**, because a count on its own just sends you hunting.

All of it is arithmetic over rows your server already holds. No new data is collected,
nothing leaves the server, and it works with AI switched off.

**A quiet shop sees nothing at all.** The card hides itself when there is nothing to say,
rather than showing seven rows of "none" - a panel that is always there is one you stop
reading, and then it is worse than absent because it still looks like it is working.

**The two money lines follow the books, not the ticket queue.** Unbilled work and forgotten
timers are shown to whoever handles billing - which includes the Accountant, who holds no
ticket permissions at all and would otherwise have been shown everything except the two
lines that are their entire job.

The weekend counts properly: a job that went quiet on Friday afternoon has not been
ignored for three days by Monday morning, and the card does not say it has.

### Three things a shop reported

**"Pull the latest release from GitHub" said the server did not respond.** The server was
working. It was downloading the release - about 50 MB - while the console gave up waiting
after twenty seconds and blamed the server for it. The console now waits as long as the
download reasonably needs, and the button says what it is doing instead.

**The canary list grew with the fleet.** Every enrolled console had a row on a page that
already scrolls. Now the machines you have pinned by hand are shown, the rest are one click
away in a scrolling panel, and a line above says how many of each. If nothing is pinned it
says so plainly, which is a real state that an empty list under a heading did not
communicate.

**The GitHub token box is gone.** The product publishes to one public release feed and
reads it with no credential, so a private feed was never something this supported - and the
only thing that box reliably produced was the failure it existed to serve: a stored token
that later expires and makes even a *public* feed refuse that one server. You can no longer
create that state.

If a server still carries a token from an older release, nothing is stranded: the status
strip says so and offers **Remove the token**, and saving the feed settings clears one too.

### Worth knowing

**Nothing here has run on real hardware** beyond the report that prompted the three
repairs. The attention card is proven against a real server over a real connection and
against its own arithmetic, not against a shop's live backlog - its cost on a large one is
not yet measured.
