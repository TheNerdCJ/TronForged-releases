# v0.442.0 - A sent invoice keeps the Bill-To it was sent with

Reprinting an invoice used to print the customer's details as they are today. A customer who moved or changed their name after paying got a copy that was not the bill they were sent. From this release, the shop server keeps the Bill-To (the BILL TO block on the printed invoice) that each invoice is sent with, and every reprint of that invoice shows it. This release updates the consoles and the shop server. The first time the updated server starts, it adds to the shop's database, and after that an older server version cannot be put back without losing data - read **Before you update**.

### Invoices

- **A sent invoice keeps its Bill-To.** When an invoice is sent - with **Send invoice** on a draft, or **Create & send invoice** on a ticket - the shop server records the customer's name, contact person, phone, email and billing address (the **Address** on the customer form) as they are at that moment.
- **A reprint shows the Bill-To it was sent with.** **Print...** on that invoice (Service Desk > **Invoices**) prints the recorded Bill-To, even if the customer has since moved, changed their phone number or email, or been renamed. So does a PDF saved from the print preview. It stays that way after a payment, a refund or a void. The rest of the page, such as payments, balance and status, shows how things stand on the day you print.
- **The next invoice uses the new details.** Change the customer's record as usual. Every invoice sent after the change carries the new details.
- **A draft still follows the customer's record.** A draft has not been sent yet, so it prints the customer's current details until it is sent.
- **Invoices sent before your shop server updated** have no recorded Bill-To. They go on printing the customer's current details, as before. Nothing is filled in for them later.
- **Check the customer's details before you send.** A name, address, phone number or email added or corrected after an invoice was sent does not appear on its printed copy - and neither does an address that was missing when it was sent. To see what a sent invoice carries, press **Print...** and look at the preview. To bill the corrected details, use **Void & reissue** and create a new invoice. If a payment was taken on it, use **Record a refund** first, as the Service Desk says. That only records the refund in your books - it sends no money back - so record the payment again on the new invoice. Both the refund and the new payment appear in your QuickBooks exports.
- **Only the printed invoice changes.** The invoice as shown in the Service Desk, the invoice email (sent to the customer's current email address) and QuickBooks exports still use the customer's current details.

### Before you update

**This update cannot be undone just by installing an older server version.** Once the updated server has added to the database, no older server version will open it - not even the release just before this one. Going back would mean putting back a copy of the database made before the update, together with the older server program, and losing everything entered since - tickets, invoices, payments and customers. The Server Console cannot do that for you: its **Restore database...** always uses the server program that is installed, which adds to the copy again as it puts it back. If you want to keep that possibility open:

- **Make a copy before your server updates itself.** A shop server updates itself soon after a release, when the shop is quiet. On the server PC, open the Server Console and press **Settings > Database maintenance > Back up database...** straight away - a Server Console that has just started checks for updates after about a minute and a half, and may update the server on its own. Then update by hand (see **After you update**). If an update starts first, use a daily copy instead.
- **The daily copies.** The shop server also copies its database once a day, into `C:\ProgramData\TronForged\server\backups\db\` on the server PC on a standard install (named `tronforged-<date>.db`; the folder needs administrator rights). It keeps only the newest seven, so about a week after the update none from before it is left. If you want one, copy the newest one made before the update - go by the time the file was modified - somewhere safe.
- **Neither kind of copy is encrypted.** Each holds every customer, ticket and invoice and the credentials of every enrolled console, so keep it somewhere only you can reach.

### After you update

- **Update the shop server by hand if you can:** on the server PC, **Server Console > Settings > Updates for this PC > Update everything on this PC**. Then someone is watching when it adds to the database (see **Known issues**), and invoices start keeping their Bill-To sooner.
- Nothing else needs doing. Invoices already sent, and drafts, print exactly as they did.

**While the consoles and the shop server are on different versions:**

- An updated console works with a shop server that has not updated yet, and prints every invoice with the customer's current details, as before. Invoices sent in that time never get a recorded Bill-To.
- A console that has not updated yet keeps working with an updated server. Invoices sent from it still get their Bill-To recorded by the server, but that console prints the customer's current details on every invoice until it updates.
- Nothing changes in the customer console.

### Known issues

- **If consoles cannot reach the shop server after it updates**, open the Server Console on the server PC and press **Settings > Updates for this PC > Update everything on this PC**. Your data is intact. If the updated server is slow to come up - for example while antivirus scans it - the update puts the previous server program back and may say the shop is still online, but the previous program cannot open the updated database, and the server does not try the update again on its own. This is uncommon.
- Still open from earlier releases: leave **address lookup** switched off for now - with suggestions showing, Tab moves into the list and Escape there can close the customer form (v0.441.0); unticking **Packages ship to this address** before **Mail goes to this address** can drop a typed shipping address (v0.440.0); after **Edit contact details** the Service Desk's customer card keeps showing the old details until the customer is opened again (v0.439.0); **Stop Safely** can be pushed off the screen in a console window narrower than about 780 pixels; **Choose machine...** on a ticket answers *No such machine.*; and an update can restart the console during a long Data Recovery job (v0.438.0).
