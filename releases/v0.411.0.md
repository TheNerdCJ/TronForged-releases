# v0.411.0 - v0.411.0 - a security fix in the full-control helper

## v0.411.0 - a security fix in the full-control helper, and the desktop icon finally follows your brand

**This release fixes a serious security weakness in the full-control helper. If your shop installs
that helper on customer machines, update, and update those machines. Details below.**

### Security: the helper's channel now proves who it is talking to

The full-control helper is the component that lets a technician reach elevation prompts and the
sign-in screen. It runs with the highest privileges on the machine, and the console talks to it over
a local channel.

That channel was protected by a permission list, which controls who may connect to it. What it did
not do was establish **identity** - neither side proved who it was. Two consequences followed.

**Another program on the same PC could impersonate the helper.** If it did, it would receive what a
technician types while the helper is in use, which at an elevation prompt is an administrator
password. The console would not notice, and your fleet would go on reporting that machine as
healthy.

**The channel was also reachable from other machines on the network**, by someone already holding
administrator credentials for that PC. That route bypassed the consent prompt, the arming check and
the audit record entirely, so it left no trace in the shop's logs.

Both are fixed. The connection is no longer able to lend the caller's identity to whatever answers
it, the console now verifies that the program on the other end really is the helper before it sends
anything, and the channel refuses connections from other machines. A channel taken over by something
else is now reported instead of being retried silently, and the fleet stops claiming a machine has
elevation access when it cannot be confirmed.

**What you should do.** Update the console on machines that have the helper installed; the helper
updates with it. There is no configuration change and nothing to turn on. If you want to judge your
own exposure: the risk applied to machines with the helper installed, and required either a program
already running on that PC, or someone with administrator credentials reaching it over your network.

### Your desktop icon follows your brand now

v0.410.0 fixed the icon file itself, which could not be read at all. This release fixes the other
half: the desktop and Start Menu shortcuts never named your icon in the first place, so they drew
the plain TronForged one from the program file.

They now name your shop's icon, and - the part that matters for machines already in the field - they
**check and correct themselves** rather than only being set once at install. A console repairs its
shortcuts at launch and after connecting to your server, so machines that have been wrong all along
fix themselves without anyone visiting them.

A later rebrand is noticed too. Every version of your icon is written to the same filename, so
comparing names alone would have caught the first repair and silently missed every change after it.
The check compares the file itself, so a new icon over an old name still converges.

Windows is told about each shortcut that changed, using the documented notification for it. The
product does not delete your icon cache or restart your Explorer to force a refresh - those are
common suggestions and neither is something a program should do to a customer's machine.

A machine that has not enrolled yet keeps the plain icon rather than being pointed at a file that is
not there.

### Worth knowing

**The last step of the icon chain is unproven.** A changed icon file is re-read by Windows, and the
shortcut is corrected and announced. Whether an Explorer window that is already open repaints
immediately, rather than at the next sign-in, has not been measured on a real desktop.

**One timing case is honest rather than hidden.** The background service can correct a shortcut
before anyone signs in, but a notification sent from there does not reach a signed-in user's
desktop. The shortcut file is still correct; that user may keep seeing the old icon until their next
sign-in or the next time the console starts.

**Pinned taskbar and Start items are not touched.** Those are separate private copies inside each
user profile.

**None of this has run on real hardware.** The helper security fix in particular is proven against
test doubles, not against a real installed helper service on a real customer machine.
