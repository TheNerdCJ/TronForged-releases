## v0.392.0 - the Updates page tells you why nothing is arriving

**If your consoles have stopped receiving new versions, open Server Console -> Settings ->
Console updates. This release puts the reason at the top of that page, in colour, with the
fix as a button next to it.**

### What was wrong

The page could already detect every reason updates stop. It just said so in small grey text,
below a button, underneath two input boxes, above a list of every release the server had ever
downloaded. In practice nobody saw it.

The most common reason turns out to be a setting that was correct once and silently went out
of date. Before v0.378.0, TronForged published releases to a single repository and your server
read them from there with an access token. v0.378.0 split that in two: releases now go to a
public feed that needs no token, and the source stays private. A server set up before that
keeps its old setting - and when its token eventually expires, GitHub refuses it and updates
stop. Nothing changes the setting for you.

### What changed

The Console updates page now opens with a status strip that says one of three things:

- **Green** - reading the public feed, no token. Nothing to do.
- **Amber** - reading the right feed, but a token is stored. A token is sent on every check,
  so the day it expires your updates stop. There is a button to remove it.
- **Red** - not reading the public feed at all. It names the repository your server is
  actually reading, explains that the old one is private and will refuse this server, and
  offers **Use the public feed** - one click, which also clears the stale token.

The release catalog is also no longer one long list. Releases that still need a decision from
you - a download that has not been published, or a build that has only reached your canary
machines - are listed first, under a count. Everything finished collapses behind a **Show N
finished releases** button. On a shop that has been running a while this is the difference
between three rows and forty.

### If your updates have stopped

Set the release feed to the public one (the red strip's button does it), remove any stored
token, then press **Pull the latest release from GitHub**. Your catalog will catch up in one
go.

### Known gap, not fixed in this release

If a release is held at your canary machines, the server records why in the audit log but the
Updates page does not yet show it. Server Console -> Audit log, and look for `release.autohold`.
