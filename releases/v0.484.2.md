# v0.484.2 - TronForged 0.484.2 - Update and remote sign-in fixes

## TronForged 0.484.2 - Update and remote sign-in fixes

### Connections

- Fixed: PCs at an office or site that share one internet address could drop off the shop's fleet a
  few minutes after enrolling ("Not connected right now ... Handshake failed"). The server limited
  how many connections one address could hold, and counted connected, signed-in PCs against that
  limit for as long as they stayed connected. The limit now applies only while a connection is being
  set up; once a PC has proved who it is, it no longer counts, so an office can keep as many PCs
  connected as it has.
- The protection against floods of unauthenticated connections from the internet is unchanged.

### Updates

- "Update now" no longer fails on a PC whose previous update is still on its trial run because
  TronForged there was still running the older build. TronForged on that PC now restarts onto the
  build it already has, but only when nothing is running (never during a repair run, a benchmark, a
  Windows fix or a remote session). The technician sees "it is restarting onto <version> first - ask
  again in a minute" instead of an error.
- If TronForged on that PC is already running the build on trial, its open window counts as proof
  that the build works. The trial ends and the new update is downloaded and installed in the same
  request.
- When an update really cannot go ahead yet, the message now says what fixes it: open TronForged on
  that PC once so the build on trial can prove itself, or restart TronForged there to finish a
  rollback that is owed. The old advice, "Restart that PC", did not always fix it.
- Updates are still never installed over a build that has not proved itself. The previous build is
  kept until the new one has started properly.

### Remote sign-in on Windows Server

- Ctrl+Alt+Delete on a server with no monitor now tells you why it cannot reach the sign-in screen,
  instead of saying the helper did not answer.
- When the TronForged console you are connected to runs in a Remote Desktop session (the usual way a
  server with no monitor is used), the message says so and tells you to sign that session out to
  reach the PC's own sign-in screen.
- When a user has switched away with Switch user, the message names that instead.
- When no session is on the PC's own screen at that moment, the message says so rather than calling
  a running helper "not running".
- When Ctrl+Alt+Delete reached the PC but its security screen cannot be shown (no monitor or no
  active display output), the message says so and suggests attaching a monitor or a display
  emulator plug.
- The helper now records a screen that Windows reports as having no size, instead of failing
  silently.
