# v0.449.6 - TronForged 0.449.6 - backups restore securely, Update now, Remote readiness, fleet by business or household

This release follows v0.449.5. It makes every backup restorable, and restorable securely: copies on an external backup drive are now encrypted with your shop's own key, disk images are checked before they are written to a disk, and moving the shop server's backup location now copies everything across. Backups and disk images from technician and customer consoles go to the backup location set on the Server Console. It also brings **Update now** for one PC, a fleet you can view one business or household at a time, a Remote readiness that says when a PC is *On the bench* and what it is doing, and the fixes from the field reports. The shop server's program changes too, so update the shop server first. The licence changes; the changes are listed at the end.

## Changing the backup location is safe now

Once your shop server runs v0.449.6, changing the Server Console's backup location is safe. Moving the backup location (Server Console > Backups) now **copies** every backup stored at the old location to the new one, reads each copy back to check it, and shows the progress under **Copy of the earlier location**. Until the copy has finished, the shop server still reads from the old location, so nothing becomes unreadable while it runs. Nothing is ever deleted from the old location - delete those files yourself once every item says it was copied.

## Restoring backups safely

**Backups on an external drive are now encrypted**
- File backups, registry backups and disk images copied to an external backup drive are encrypted with your shop's own key, which the shop server holds. A copy made by this release cannot be read without your shop's key; older copies and Windows system images are covered below.
- Each copy is read back and checked after it is written, before the job is called done.
- To use an encrypted disk image, choose **Open (decrypt)** on the Imaging page; choose **Close opened copy** when you are finished, and the plain copy is removed.
- Older plain images on a backup drive are marked as not encrypted, and **Encrypt** seals them. Copies made before this release stay unencrypted until you do.
- Windows system images made with Windows Backup are not encrypted by TronForged. Use BitLocker To Go on a drive that holds one.
- On the Server Console, **Backups** can now save a **recovery key** - a file protected by a passphrase you choose. Keep it somewhere safe and away from the shop server. With it, a technician can open an encrypted drive copy even when the shop server is not available (**Use a recovery key...** on the Restore page).

**Restoring from a drive**
- The Restore page has a new **From Drive...** row that lists the backups on a drive and restores one, checking every file as it goes (a copy made before this release has nothing to check against, and the restore says so).
- A saved registry key (.reg) can now be imported from the registry backup list. You are asked first, and every import is recorded.

**Disk images are checked before they are written to a disk**
- When an image is captured or downloaded, the shop server signs a record of its contents. Before a restore, the console checks the image still matches that record, and the restore itself checks it again. An image that does not match, or that was never signed, is only used after a technician types an override, and the override is recorded.
- A restore now names the target disk by its serial number and size, not only by its number, and checks it again just before writing. If the disks were re-plugged and the numbers moved, the restore stops instead of writing to the wrong disk.
- A disk holding the external backup drive or the image library is marked PROTECTED. Restoring onto it - or onto a disk that cannot be measured - asks you to type a phrase naming the disk, and the shop server records that override before anything is written; if it cannot be recorded, nothing is done. **Clone to disk** asks the same: after its capture it asks for the phrase, the shop server records the override as a clone, and if the override is refused the image it captured is kept. The disk Windows is running from can never be overridden, for a restore or a clone.
- Images are applied and browsed with Windows' own integrity checking turned on.

**On the shop server**
- Downloading a disk image now needs the backup restore permission, checked by the shop server. A customer's own sign-in, and each person on a business customer's account, can download that customer's file backups but not its disk images.
- Long backup lists are fetched page by page, so every backup is shown and counted, not only the newest.
- The customer-managed encryption key, the escrow and the snapshot features have been retired. A backup made with a customer-managed key can no longer be restored by the shop; the console says so.

## Backups and disk images go to the Server Console's backup location

- **"Shop server" means the backup folder or NAS set on the Server Console.** On the Disk images page, choosing Shop server now hides the image folder box and the drive list and shows where the temporary copy is made on this PC (a second internal drive with room, never the drive being captured). If no drive can hold it, the page says so. Once the shop server has stored the image and read the whole of it back successfully, the temporary copy is deleted from the PC; if the upload or that check fails, the copy is kept so it can be sent again. Choosing Both still keeps a copy on the external backup drive.
- **"Select External Backup Drive"** replaces "Add a shop drive...". An external drive is any drive except the Windows drive - a second internal disk or a USB drive - and selecting it is enough; there is no separate confirmation question any more.
- **Customers can send their own files to the shop.** The customer console's Backups page has a new **Back up files to my shop** button. The files are filed under that customer only and count toward the customer's storage allowance - set a storage allowance for the customer on Customers & fleet first, because a new shop server allows none.
- **The Server Console's Backups page says more.** Each backup now shows whether it is a file backup, a registry backup or a disk image, its size, when it was stored and whether its copy is verified. The page also explains that the backup folder holds numbered folders of encrypted .chunk files rather than .zip or .wim files, so that is not a sign anything is missing. It also lists any earlier backup locations.
- **A customer's backup list is complete.** A customer whose backups were older than the shop's most recent ones could be told they had none; that is fixed.

## Update now: update one PC from the fleet

- On the Fleet and remote page, when a PC's readiness says "Update TronForged on that PC to <version>", the selected PC now has an **Update now** button under that line. Pressing it asks that one PC to update to the newest release your shop server has.
- The PC runs its ordinary update: the same download, the same signature and hash checks, and the same automatic roll back if the new build does not start. Nothing about what is trusted changes.
- An unattended PC restarts TronForged onto the new build as soon as no remote session is open. On a PC where someone is using TronForged, the usual notice comes first. A service run is never cut: the update waits until the run finishes.
- The button shows how it is going: **Asked to update**, **Updating...**, **Updated to <version>**, or why it did not finish and what to do next, with **Update now** to try again. A PC that is switched off shows **Will update when the PC next connects**.
- A PC on a TronForged older than this release cannot take a request straight away. It shows **At its next check** and picks the version up at its own update check, within six hours.
- The request skips the rollout stages for that one PC and that one version only. Every other PC still follows the rollout.
- Your shop server refuses the request, and says why, when the PC already runs the newest release, when the PC is too old to go straight to it, or when the PC has not reported its version yet.
- Only accounts with the remote permission see the button (technicians and administrators). Reception, Accountant and customer logins do not. Each request is recorded in the Audit log with who asked.
- The same **Update now** item is on a PC's tile menu on the Unattended Fleet dashboard.
- It updates one PC at a time. There is no "update all" yet.
- A PC whose system helper is older than its console, but whose console is already on your newest release, shows no Update now button: there is nothing newer to send.

## Remote readiness says "On the bench", and what the PC is doing

The remote readiness on the Fleet and remote page (the list, the detail panel) and on every fleet tile now tells you two more things about a PC.

**On the bench.** The PC reads *On the bench* when it has proved it is on your shop's own network. Your shop server tells each enrolled PC its local-network address. Every 5 minutes, and sooner after the PC's network changes, the PC connects to that address and completes the same identity-checked connection it uses for everything else. A ping does not count. Neither does some other device answering at that address, a PC that reaches your shop over a VPN, or a server that is not your shop's. The proof lasts 15 minutes. A PC that stops checking in is no longer shown as on the bench within 5 minutes.

**What it is doing.** While a PC is working, its readiness says so:

- *Running Automated Services*: the Automated Service page, a remote run of it, or **Run maintenance now**.
- *Running Manual Services*: Manual Stages, Windows Fixes, or a Manual Tools program while it is open.
- *Running Scheduled Maintenance*: the maintenance schedule's own run.
- *Running Local Backup*, *Running Cloud Backup*, *Running Local Restore*, *Running Cloud Restore*, *Running Local Image Backup*, *Running Cloud Image Backup*, *Running Local Image Restore* and *Running Cloud Image Restore*. Each is followed by the time left, worked out from the transfer's measured speed, such as *about 12 min left*, *about 1 h 20 min left* or *less than a minute left*. Until the speed is measured it reads *estimating time left*. Where the work reports no size it reads *time left not known*: a disk image capture or restore, the check and encryption that follow an image capture, or a copy to or a restore from an external backup drive.

**Cloud** means your shop server's backup store, the location set on the Server Console. **Local** means a drive on, or attached to, the PC.

A PC that is on the bench and busy shows both, for example *On the bench - Running Automated Services*. If several things run at once, the readiness names the first of these: an image restore, a restore, an image backup, a backup, an automated run, a manual service, then the schedule. A PC that has not checked in for 5 minutes is not shown as running anything.

The readiness check that used to be called *On the bench* (*A service run is in progress*) is now called **Repair run**. "On the bench" means only the network proof now. PCs and shop servers older than this release show their readiness as before.

**Also fixed:** a PC whose stored device credential could not be read believed it had proved itself to the shop server, but it had not. It now says so and stops there.

## See one business or household at a time

- **The Fleet and remote page has a new bar above the PC list:** **All / Businesses / Households**, then **Customer**, **Site** and **Agent group** pickers. Each picker has a search box and shows how many PCs (and how many online) each entry holds. Choose a customer and only that customer's PCs are listed; the counts at the top - PCs, online, need attention - are that customer's, and the search looks within them.
- **Businesses and households are listed apart.** The Customer picker groups your customers under **Businesses** and **Households** (the type set when the customer was added or edited), plus **Not assigned to a customer** for the shop's own PCs and anything not yet filed. **Businesses** or **Households** alone narrows the list by type without picking one customer.
- **Filter by site and agent group.** For a business, choose one of its sites (or **Not in a site**) and then one of that site's agent groups. You can also pick a site or an agent group directly - they are listed as *Customer > Site* and *Customer > Site > Agent group* - and the customer is selected with it. Households have no sites or agent groups, so those pickers are hidden while a household is chosen.
- **The fleet dashboard has the same bar.** The Unattended Fleet tile board shows only the chosen customer's, site's or agent group's tiles, and its status bar counts what is shown.
- **Your last choice is remembered** on each console. If that customer, site or agent group has since been deleted, the bar says so and shows the next level up instead.
- Against an older shop server every customer is listed under **Customers** and the bar says the server needs updating to sort them. Nothing new is shared: each account sees only the PCs it could already see.

## Fixes from the field reports

- **No more "C:\Program" warning after a clean-up.** Some virus scanners split a folder path at its first space and left an empty file called C:\Program behind, so Windows warned about it at sign-in. TronForged now gives every scanner a path with no space in it, and the WrapUp stage removes an empty C:\Program or C:\Programs file that appeared during the service - only an empty file, never a folder, never one that was there before - and the service report says so.
- **PowerShell 7 installs again.** On a PC that had never had PowerShell 7, Microsoft's installer put it one folder too deep, so TronForged removed it again, and the fallback could not finish either. Both are fixed, and if moving PowerShell into place ever fails, the message now says Windows' own reason.
- **The ".NET 10 Desktop Runtime" line in Settings > Prerequisites is never blank.** It now always says whether .NET 10 is installed and whether this console is using it.
- **A console no longer crashes when TronForged is started a second time while it is open.** Opening TronForged again (or an update starting it) used to rewrite the console's own program files under it; it now leaves files that have not changed alone, and waits for a running console to close before replacing any.
- **Fewer false crash reports.** A connection the console gave up on after a timeout was being reported to the shop server as a crash, hundreds of times per version. That is fixed, and any crash of this kind that remains now says what actually failed.
- **The shop's desktop icon problem is easier to track down.** When Windows does not answer while TronForged updates a shortcut's icon, the report now says which shortcut and which step.
- **A data-folder permission check that cannot finish now says which file and why.**

**The software-health report (Server Console > Settings)**
- A crash that carried on from one version to the next is now listed once, under "STILL HAPPENING", instead of showing as new, regressed and gone at the same time. "GONE" now means quiet on every version.
- Each stage line names its most common reasons.
- A tool your PC's older tool list asks for but this version no longer downloads is listed under "Not downloaded on purpose", and a repair a PC made to itself (such as a re-made unattended-access token) under "Put right on the PC" - neither is counted as a failure.
- New signed versions of scan tools that change often are no longer flagged as something to act on.
- Silent machines show when the server last heard from them and which version they last ran.

## Before you update

- **Update the shop server first** (Set up server > Update server, on the server PC), then the consoles. On its first start the shop server adds one new table (each PC's latest Update now request); nothing already there is changed. Going back to an older server release needs the database snapshot taken before the update, as for earlier releases.
- **With an older shop server**, a disk image sent to the shop server alone keeps its temporary copy on the PC, the fleet cannot be sorted into businesses and households, **Update now** is not offered, and no PC is shown as *On the bench*.

## After you update

- **Save the shop's recovery key**: on the Server Console, **Backups > Save the recovery key...**, with a passphrase you keep somewhere other than the server. Keep that file, with a copy of the shop server's backup (.tfbak) and its server.dat, somewhere off the server. The setup guide explains why.
- **If you want to move the backup location, you can now** (see the first section). Delete the files at the old location yourself once **Copy of the earlier location** says every item was copied.
- **For *On the bench*:** from the bench, the shop server must be reachable at its own local-network address on its listening port (8791 by default) - the same port LAN enrolment already uses.

## The licence

The licence changes in these places:

- **Section 6.3** now describes **Update now**: a technician with the remote permission can send the newest release to one computer ahead of its rollout; it is verified like every update, recorded in the audit log, and the Software restarts only once no remote session is open and no service run is in progress. **Section 18.1** (for the customer) says your shop can also update the Software on your computer at once.
- **Section 11.1** now describes the restore and clone overrides: onto a disk holding the external backup drive or the image library, or a disk that cannot be measured, only after a typed override the shop server records - never onto the running Windows disk - and an image the shop server has not signed is used only after a recorded override.
- **Section 12.2** says a console also reports what it is doing (a service run, a maintenance run, a backup or restore and where it goes, with the time it expects to take) and whether it has proved it is on the shop's own network.
- **Section 12.5** lists two more things the Software deletes on its own: the temporary copy of a disk image sent to the shop server alone, once the shop server confirms its copy, and the plain files written while a disk image is encrypted on an external backup drive.
- **Sections 13.1, 13.2 and 13.3** describe the encrypted drive copies and the recovery key, that only accounts with the restore permission download disk images, that the customer passphrase option and its escrow are gone, and that moving the backup location copies everything and deletes nothing. **Section 20.1** (for the customer) says your own sign-in can download your file backups but not a disk image of your computer, and **Section 21.4** lists the retired passphrase backups and snapshot store.

## Not yet tested on hardware

None of the changes in this release has been tested on real hardware yet; they have been exercised by the automated checks only. That includes the encrypted drive copies, the restore and clone overrides on real disks, moving the backup location on a real NAS, **Update now** on a real fleet, and *On the bench* on a real shop network. If consoles cannot reach the shop server after it updates, use **Update everything on this PC** on the server PC.
