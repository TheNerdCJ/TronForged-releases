# v0.449.8 - v0.449.8: the Apps page

This release follows v0.449.7. It adds one page to the technician console: **Apps**, a catalog of apps for this PC that installs, updates and removes them through winget, Microsoft's own package manager. The shop server's program is unchanged apart from its version number. The licence gains one sentence about the Apps page (below).

## The Apps page

- **Apps** sits under **Install and tune**, after Reinstall. Anyone who can open the Reinstall page can open it.
- It has four lists: the shop's own catalog of common apps (with their icons), **On this PC** (everything winget can see installed), **Updates** (what winget can bring up to date) and **All of winget** - every package in the winget catalog, about 15,700, read from winget's own copy on the PC.
- Each row says what is true on this PC - *Not on this PC*, *Installed 26.03*, or *26.03 -> 26.04* - and offers **Install**, **Update** or **Remove**. Those buttons only add the app to **Changes for this PC**; nothing runs until you press the button there and confirm.
- **The confirmation lists every app.** It says that running them accepts each app's licence (its package agreement) on the shop's behalf, and it asks before any removal.
- Changes run one at a time, silently, and each line ends with what winget's result code says happened: *Installed*, *Already installed*, *No installer for this PC's Windows or processor*, *Restart Windows, then run this again*, and so on. A failure does not stop the rest, **Retry** puts it back, and **Stop after this app** never stops an installer half-way. The PC is read again afterwards only if a change actually ran.
- The **Reinstall** page's app packs now go onto this same list (**Add to Apps**).
- **Note on permissions:** the Reinstall permission now also lets its holder remove programs from the PC, through the Apps page. There is no separate permission for removal.

## Safety

- **The console runs only Microsoft's own App Installer.** A `winget.exe` found anywhere else on the PC - for example one placed in a folder an ordinary user can write to - is refused, and the page says where it was found.
- **While the Apps page is running changes,** a service run, a remote run or a scheduled maintenance run on the same PC will not start, and says why. In the other direction, the Apps page will not start while a service run is in progress.
- A console running as the SYSTEM account (a service or a remote session through it) cannot reach winget, which is installed for each Windows user; the page says so instead of reporting winget missing.
- Older versions of winget shorten long package ids in their lists. Those rows are left out rather than offered with an id winget could not act on, and the page says how many were left out.

## Not yet tested on real hardware

- No install, update or removal has yet been run from the console on a real customer PC. The result codes come from winget's published list, not from watching each one happen. Some installers refuse to run elevated (Spotify's is one); the line says so rather than claiming success.
- What the Apps page does is not yet written onto the working ticket or the service report.

## Licence

- **Section 5.3 gains one sentence:** the Apps page runs winget for the apps a technician chooses to install, update or remove, accepting their package agreements on the shop's behalf; each package is left to winget's own checks, and each app remains subject to its publisher's terms. Nothing else in the licence changes.
