# v0.460.0 - TronForged 0.460.0 - tighter server checks, less personal data in logs, and offline sign-in that honours two-factor

## TronForged 0.460.0 - tighter server checks and less personal data in logs

### The shop server
- When a request fails inside the server, the console now sees one plain sentence instead of the server's internal error text. The details go to the server's own log.
- Chat messages, presence (available, away, busy), invoice dates and invoice line kinds (labor, part, fee, discount) are checked before they are saved. Something that does not fit is refused with a sentence that says why.
- If any customer is kept off AI, a customer summary is refused for a run that is not filed under a ticket, because the server cannot tell whose computer it was. Attach the run's report to its ticket (Files > Attach a file...) and draft the summary from there.
- Passwords, keys and other secrets are removed from audit log entries before they are saved.
- The folder that holds the daily database copies is locked down again before each day's copy, not only once when the server starts.
- A deleted backup can only ever remove that backup. The server refuses any request to delete its database copies or shared storage folders.
- Behind Cloudflare, the server's limits on repeated requests now count each real client, not Cloudflare itself.
- Address lookups and the run webhook connect only to an address the server has already checked. Addresses inside your own network are refused, including IPv6 forms of them.
- The "this console is on the server box" shortcut now needs proof. The Server Console proves it by itself. A port forwarder or other program on the server box no longer gets the shortcut.

### The consoles
- Server Console > Email: you can now set the run webhook address there. A signing secret is shown once when it is made, with a Copy button.
- The Cloudflare API token in the dynamic DNS window is hidden as you type it.
- The support bundle no longer includes the job history. Text logs are cleaned of personal details before they go in, and a CONTENTS.txt file lists what was included and what was left out.
- A ticket reply that looks like it contains a password is not kept as a draft on the PC. The reply box reminds staff that device passwords belong on the ticket's Device password card.
- Card numbers are now masked in the repair engine's diagnostic records too.

### What to do
- Update the shop server and the Server Console on the server box together. Until the Server Console on the server box is updated, signing in from it needs an enrolled PC, and managing the server from it needs the server.manage permission.
- To use the run webhook, open Server Console > Email, enter the address and save. Copy the signing secret it shows, because it is not shown again.
- No database change. Going back to the previous version needs no restore.

### Also in this release (0.459.0 was not released on its own)

#### Offline sign-in on shop laptops
- A technician laptop that signs in offline now honours two-factor sign-in. Setting up or clearing an account's authenticator, or its two weeks to set one up running out, ends that account's offline sign-in on every laptop, the same way a password reset, a disable or a delete already did.
- Giving an account or its group a new permission no longer ends its offline sign-in. Taking one away still does.
- The check runs when the sign-in window opens with the shop server reachable, and, on a laptop set up for the Windows sign-in screen, within about a minute from the before-login agent. Before, it ran only at an online sign-in or while signed in.
- Each offline sign-in the server ends is written to the server's audit log as `offline.stale`.
- A customer's portal login never gets an offline sign-in on any PC.
- If a laptop's clock is more than 5 minutes behind the time of its last online sign-in there, the offline sign-in is refused and the window says the PC's clock is behind. Correct the clock and it works again.

#### Unattended access
- A customer PC whose unattended token was refused for a reason no longer offers that token to the shop's fleet list and never hands it to a technician who asks for unattended access. Its diagnostics tell the shop why.
- Installing over an old loose copy of TronForged replaces a token that folder let other Windows accounts read, once.

#### Accounts and groups
- An account that must change its password, or has not set up two-factor in time, gets no team chat until it has.
- The founder's group can no longer be edited, deleted or replaced by an import in a way that would lock the shop out.
- When a console older than this release saves a group, the server keeps the permissions that console does not know about. An older console can still add **refunds**, the stock permissions, **tax.manage**, **erase** or **migration** to a group, but cannot take one away until it is updated.
- A new ticket is never linked to a console the shop has revoked.
- The **Customer** group preset now explains how a customer's sign-in is matched to their record by email.

#### What to do
- Update the shop server first, then every console. Until a console is updated, it cannot remove the newer permissions from a group.
- Make sure each shop laptop's clock is set automatically. A laptop whose clock is far behind cannot sign in offline.
- Staff who use a laptop offline should sign in online once after setting up their authenticator, so the laptop holds a fresh offline sign-in.
- No database change: going back to v0.455.0 needs no restore.
