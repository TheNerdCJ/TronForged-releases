# v0.484.0 - TronForged 0.484.0 - Windows Server management, and better recovery in PC Transfer

## TronForged 0.484.0 - Windows Server management, and better recovery in PC Transfer

### Windows Server management

- A new Windows Server tab appears on a technician console running on Windows Server 2022 or later,
  for staff who hold the new "Windows Server management" permission (on by default for technicians;
  off for Reception and Accountant). Older Windows Server versions show "not supported"; workstations
  and customer sign-ins never see it.
- Sections follow what the server runs: Users, Groups and Computers on a domain controller (Local
  users and Local groups on other servers), Virtual machines when Hyper-V is installed, and Cluster
  when Failover Clustering is installed.
- Domain changes on a server that is not a domain controller are refused with a plain sentence.
- Every change is authorised by the shop server at the moment it is made and recorded in the audit
  (technician, PC, action, object, result) - never a password.
- Changes that cannot be undone ask for confirmation; destroying a cluster, removing a node, deleting a
  clustered VM and removing a moved VM's original need the name typed.
- Deleting a virtual machine offers a backup first; the delete happens only after the backup is checked.
- Guided cluster setup: choose servers, install Failover Clustering (a needed restart is shown, never
  done for you), run the cluster check, name and address, witness, create - one page per step (Set up a
  cluster...), with a Clean up button if a step fails. Moving a VM onto the cluster is its own page-per-step
  wizard (Move a VM onto the cluster...).
- Virtual machines on a cluster: list, create on a Cluster Shared Volume, start and stop, move between
  nodes, change memory and processors, make highly available, delete with backup.
- Move an existing VM onto a cluster: checks first, a backup, live or planned move (the downtime is
  shown up front), and the original is only removed after the moved copy is confirmed running.
- From the fleet: a "Windows Server" button on a server's row works over the live remote session.
  If the connection drops, the page says the result is unknown - never a false success.
- The SYSTEM helper must be installed on the server (Settings) for any change to run.

### Better recovery in PC Transfer

PC Transfer now gets more of the customer's files and programs back, especially from the drive of an old PC that no longer starts. A file that cannot be read from a failing drive is skipped and listed, and the rest of the copy carries on. Running the transfer again picks up where it stopped, without copying files twice or leaving duplicates. Before copying, the new PC checks it has enough free space. Documents and Desktop folders that OneDrive or a redirect moved are found where they really are. A user whose settings file is damaged is still listed, so their files can be copied. The technician can also add any other folder from the old disk, and it lands in "From old PC" on the new Desktop. A damaged drive is now told apart from one locked by BitLocker, and a damaged drive gets the advice to image it before any repair. Over the network, a full disk on the new PC stops the transfer with that reason instead of retrying. A USB package leaves out a file it cannot read instead of failing as a whole, and loading the package again picks up where it stopped. Bookmarks now come from every Chrome and Edge profile. Microsoft Store apps are listed. The summary counts the Outlook data files that came, and says which programs still need their licence moved.

### Programs from a dead PC's drive

When the old PC will not start and its drive is connected to the new PC, programs that winget cannot install are no longer left for the technician to find. TronForged first looks on the old drive for the program's own installer and runs it silently, but only when it is signed by the program's maker. If there is no installer, it copies the program across: its folder, its registry settings, its shortcuts, and the background services and scheduled tasks it used. Drivers and security software are never copied, and neither are programs whose licence must be released first. The customer's own settings for each program are then put back. The summary says how each program came across. A copied program is marked so the technician knows it may need reinstalling.

### Licence and privacy

- The licence (section 10.11) and the privacy policy (section 4.1) now describe Windows Server
  management: what a technician can change, that each change is authorised at the moment it is made,
  the backup offered before a virtual machine is deleted, and what the shop's server records.
- The licence (sections 13.5, 13.6 and 13.7) now describes the PC Transfer changes: the extra folders
  a technician can copy from the old drive, the files a transfer skips and lists, how a BitLocker-locked
  drive is told from a damaged one, and programs installed from their own installer or copied from the
  old drive.

### Bench run (owner)

1. A test domain controller (Server 2022): sign in as a technician, open Windows Server, list users,
   create a user with "must change at next sign-in", reset it, unlock it, delete it (typed confirm).
2. A member server: confirm only Local users and Local groups show, and a domain op is refused.
3. A Hyper-V host: list VMs, stop (graceful and forced), checkpoint, delete with backup to a folder;
   confirm the export folder holds the config and every disk before the VM goes.
4. Two nodes in one domain: guided cluster setup end to end, with a file share witness; then create a
   clustered VM on a CSV, live-move it, delete it with backup.
5. Move a standalone host's VM onto the cluster (live and planned); confirm the original stays off and
   renamed until removed with the typed name.
6. From another console's fleet: open the server's Windows Server window during a live session; pull
   the network mid-action and confirm "the result is unknown".
7. Confirm Win32_OptionalFeature names DirectoryServices-DomainController, Microsoft-Hyper-V and
   FailoverCluster-FullServer on each box, and the Win32_ServerFeature IDs 10, 20, 49.
