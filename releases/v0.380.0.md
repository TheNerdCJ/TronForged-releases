# v0.380.0 - The consent screen tells the truth

## v0.380.0 - the consent screen tells the truth

The screen where a customer agrees to let their repair shop connect to their PC has been rewritten, because it said four things that were not so.

- **It promised an on-screen notice that does not always appear.** The notice is drawn by TronForged itself. While TronForged is running, a notice stays on screen the whole time a technician is connected - but when it is closed, or before anyone has signed in, the background service takes the session and there is no notice at all. The text now says that plainly, and says what happens instead: the session is written to the PC's log and TronForged reports it the next time it starts.
- **That report is now reliable.** It used to be marked "shown" before the notification was actually raised, so a notice the customer never saw - notifications off, focus assist on - was lost for good. It is now marked shown only after it appears, and comes back on the next start if it did not.
- **The box no longer defaults to Yes.** Pressing Enter used to grant a shop standing, unattended access to the machine. It now defaults to No. *Shops: after imaging, a customer who taps Enter on this box declines and it stays declined - use the tray's Connect to my repair shop to offer it again.*
- **It named a control that does not exist.** "Disconnect from shop" was never a menu item in any build. The tray item is **Connect to my repair shop**, and while connected that item disconnects. Nine places in the documentation said the old thing.
- **It now names what connecting installs**: start-with-Windows, the background agent service, the helper service that answers administrator prompts, and the firewall rules - and that TronForged goes on starting with Windows after a disconnect until you switch that off or uninstall.

Both enrolment routes - the approval window and the tray - now show the **same** disclosure, from one place in the code, so they cannot drift apart again.
