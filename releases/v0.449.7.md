# v0.449.7 - v0.449.7: sleep prevention and Ultimate Performance fixed, reports fit Letter, labels print whole, Walk-in Repair and Consultation, technician sign-out

This release follows v0.449.6. It is a release of small fixes: the automated service keeps the PC awake again, Ultimate Performance can be added again, every report prints cleanly on US Letter, the customer's name is no longer cut off the top of a DYMO label, and closing the technician console now signs the technician out. It also renames "In-house repair" to **Walk-in Repair**, adds a **Can be scheduled** box to every job type, and shows the PC's name on the customer console's Home. The shop server's program changes too, so update the shop server first. The licence changes in one sentence (below).

## Repairs and reports

- **The automated service keeps the PC awake again.** Since it was added, sleep prevention never actually switched on ("Value was either too large or too small for a UInt32" in the log), so a long scan could be cut short by the customer's sleep timer. It now switches on at the start of the run, and the log records when it is released, or why it could not be.
- **Ultimate Performance can be added again**, from the Power tab and by the Optimize stage. Both were asking Windows for the wrong plan, so it never appeared. If Windows still refuses, the message now repeats what Windows actually said instead of guessing that your edition does not support it.
- **Every report prints cleanly on US Letter**: the service report, the battery, storage, system, triage, QC, network, recovery, memory, licence and forensic reports, the fleet's device health report, and the copy of Windows' own battery report. Long file paths and wide tables wrap to fit the page instead of running off the edge, rows and headings are not split across pages, and titles that were white on a coloured band print dark on white paper.
- **Invoices and forms ask the printer for two-sided printing** (long edge) when the printer supports it. Other printers are left on their own setting. Labels are unchanged.

## Customer labels and the console

- **The customer's name no longer gets cut off the top of a DYMO label.** The label is now laid out inside the area your label printer's driver says it can print, instead of starting at the very edge of the label.
- **The console no longer closes when Windows fails to read one of its fonts while drawing a screen.** It switches to the standard Windows font for the rest of the session, records what happened for your shop's diagnostics, and keeps running.

## Job types and booking in

- The **"In-house repair"** job type is now called **Walk-in Repair** (renamed on your server only if you had never renamed it yourself).
- Every job type has a **Can be scheduled** box (Server Console > Service desk > Job types). Book in a job offers a technician, a date and time, and the reminders for any ticked type; Remote support and Service call still need their appointment.
- A new **Consultation** job type is added (can be scheduled, no device needed), and **Other** can now be scheduled. Your own job types and names are left as they are.
- Unticking **Can be scheduled** on a job type means a job of that type is booked in without an appointment - including from a technician console that has not been updated yet - and the book-in says so.
- A job type you add starts with **Can be scheduled** ticked; untick it if that type never takes appointments.

## Signing out of the technician console

- **Closing the technician console now signs the technician out** of the shop server and removes that sign-in from the PC, then closes TronForged. The next launch asks for a sign-in.
- A one-click **Sign out** is in the technician console's title bar and tray menu.
- If an Automated Service, a manual stage, a remote session or a report upload is still running, closing does not stop it: TronForged stays in the notification area, says so, and signs out when it finishes. Pressing **Sign out** during a run asks first, and waits for the run by default.
- **The licence's sentence about offline sign-in now mentions sign-out** (section 9.5): the saved offline sign-in on a PC is also removed when the technician signs out or closes the technician console.

## Adding new PCs, and the customer console

- When a customer asks the shop to add their PC, the waiting window now shows only the number to read out and "Waiting...". The technical note about which port the request came in on now goes to the shop instead: it appears on that machine's card in **Machines waiting for approval**, and in the server log.
- If your shop's public name is behind Cloudflare's proxy (orange cloud) and the server's DNS upkeep can see that, the pairing card's **Away from the shop** address now gives the web transport's port (for example :8443) instead of :8791, so a new PC outside the shop can get in.
- The customer console's Home now shows **Device Name:** under the greeting - the name this PC has in your shop's fleet.

## Before you update

- **Update the shop server first** (Set up server > Update server, on the server PC), then the consoles. On its first start the shop server adds one setting to each job type (Can be scheduled), adds the Consultation type, ticks Other, and renames In-house repair only where you never renamed it; nothing else already there is changed. Going back to an older server release needs the database snapshot taken before the update, as for earlier releases.
- **With an older shop server**, job types keep today's scheduling (only Remote support and Service call), and no new type is added.

## After you update

- **Print one customer label** from a customer's profile (**Print label**) and check that the name and phone are both on the label, with nothing cut off along the top.

## Not yet tested on hardware

None of the changes in this release has been tested on real hardware yet; they have been exercised by the automated checks only. That includes sleep prevention and Ultimate Performance on a real PC, printing reports and two-sided invoices on a real printer, a DYMO label from a real LabelWriter, and signing out with a run in progress.
