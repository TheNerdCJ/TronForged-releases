# v0.400.0 - v0.400.0 - restoring an image lays out the target disk

## v0.400.0 - restoring an image lays out the target disk

**Restoring a .tfimage onto a replacement disk now works. Before this release it erased the
target and then failed - three different ways, on an ordinary Windows machine.**

### What was wrong

A .tfimage recorded the drive letters the source machine happened to be using at the moment it
was captured - `C:` for Windows - as though they were facts about the image. The restore replayed
them onto the new disk.

On a stock Windows 10 or 11 disk that fails three ways, and all three fail *after* the target has
already been erased:

- The restore asked for drive letter `C:`, which on the technician's machine is the running
  Windows.
- The partition set to fill the remaining space was Windows, which is not the last partition on a
  Microsoft layout - so it took the whole disk and the recovery partition that follows it had
  nowhere to go.
- The step that writes the boot files looked for a drive letter on the EFI System Partition. A
  real EFI System Partition does not have one. That check ran after the entire Windows image had
  been written, so the disk was erased, filled, and then abandoned one step short of bootable.

None of this was caught because the automated tests built their sample disks with drive letters
that a real disk never reports - every partition had one. A test disk where everything has a
letter cannot show up a fault that only happens when two partitions do not.

### What changed

An image now records the **shape** of a disk, not the letters one machine was using. Drive letters
are worked out against the disk being restored to, after the partitions exist, and handed back
afterwards. The EFI System Partition is found by what it is rather than by a letter it never had.
Windows is still the partition that grows into a larger disk, but it now gives back exactly the
room the partitions after it need.

Also in this release:

- **Images captured by earlier versions restore too.** Nothing needs re-capturing and nothing is
  migrated - the older images were always fine, it was the restore that could not use them.
- **A restore that cannot succeed now refuses before it erases anything**, and says what is wrong
  with the image rather than stopping halfway with the disk already gone.
- **The recovery partition is now named for what it is.** It was being filed as an ordinary data
  volume, and on a machine with a second drive that could have sent a large data volume into the
  990 MB recovery partition. It is also now disclosed: a restore tells you plainly that the
  recovery partition is recreated empty, which was true before and went unsaid.
- **A capture that cannot take a snapshot says so.** The message explaining why - and the fallback
  that captures an external drive directly when nothing is writing to it - could never run,
  because of a fault in how the warning was returned. A failed snapshot produced only
  "DISM capture failed".
- **Free-space checks work on a network share.** The check that makes sure there is room before a
  capture starts silently gave up on any `\\server\share` path.
- Verifying an image is faster, and a restore no longer re-checks every file twice.

### What this release does NOT do

Restoring a machine onto **its own** disk still needs bootable recovery media, and that media does
not exist yet. This release makes restoring to a *replacement* disk work - which is the bench job
where the old drive comes out and a new one goes in. For a machine that will not start, the image
is still recovered by taking the disk out.

Also still absent, and on the list: restoring onto a smaller disk, disk-to-disk cloning,
BitLocker handling, scheduled captures, and retention that deletes old images.

### Worth knowing

Nothing in the imaging feature has ever run on real hardware - that has always been true and is
now written down where it belongs. This release makes the automated tests able to see a fault
class they were structurally blind to, which is the prerequisite for trusting a bench run, not a
substitute for one.
