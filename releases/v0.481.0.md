## TronForged 0.481.0 - A zero-typing support download, phone access for technicians, two-factor for customers, and reports that file themselves

### The support download needs no typing

The customer no longer types an address. The file they download from the PIN page carries your shop's address in its name, and the Allow prompt now leads with the address the program actually connected to. If the name was changed and Windows cannot say where the file came from, the program tells the customer to call their technician.

### Technician phone access

An optional, small web page at /tech on your server lets a technician accept or decline a PC's request to join the shop, and read the list of your PCs, from a phone's browser. It is off until an administrator turns it on in the Server Console's settings, and it offers no remote control, scripts or settings. It always needs a password and an authenticator code, even if two-factor sign-in for staff is turned off.

### Two-factor sign-in for staff and customers

Two-factor sign-in now covers customer portal accounts as well as staff, with a separate switch for each in the Server Console's settings. Both are on by default. New accounts set up an authenticator at their first sign-in; existing customer accounts have two weeks from their first sign-in on this release. Turning a switch off asks you to confirm and deletes nothing. Turning it back on gives accounts with no authenticator two fresh weeks.

### Reports reach the ticket after the technician signs out

When a service run starts from a ticket, the PC can send that run's report, receipt and work record to that ticket by itself, even if the technician has signed out. It can add only to that one ticket, from that PC, for up to 14 days. Upgrading adds one small table to the server's database.

### Authenticator codes sign you in by themselves

Every screen that asks for an authenticator code now uses one code box. It signs in by itself at the sixth digit and accepts a pasted code with spaces or a hyphen. A wrong code keeps the box open and says why, and the same code is not sent twice unless you press the button.

### Customers can connect from the connection card

A customer console that has never connected now shows a place to enter your shop's pairing code on its connection card, so the customer can connect it there. Every connection state on the card offers something to do next.

### Phone numbers format themselves

Phone numbers now format as you type and show the same way on every screen and printout. Numbers already saved are not rewritten, and searching by digits finds them however they are displayed.

### Fewer failed runs and clearer reasons

Service runs now cope better when a Windows module or a system read fails, and they record the actual cause when a step cannot continue. Temporary-file cleanup keeps the .NET folder, the Emsisoft scanner reports why it stopped, and every step records how long it took. The console no longer closes over a font failure or a full log box, and data migration connections give up on time instead of hanging. An update that has already been installed no longer shows a false warning.

### Licence and privacy

The licence (EULA.md) and the privacy notice (PRIVACY.md) now describe two-factor sign-in for staff and customers, technician phone access (new clause 10.10) and service reports sent after sign-out (new clause 12.7). They also say that a frozen console may save a small memory dump to its own logs folder, which leaves that PC only in a Support Bundle you choose to make.

### Before you rely on it

The phone page has been tested over a real encrypted connection, but not yet in a real iPhone or Android browser. Please try it on your own phones first.
