## v0.405.0 - browsing an image has a Close button, and both ends of it tell you how long they will take

**Browse Files was secretly also the Close button, closing the console froze it for minutes, and
nothing ever said that opening a big image takes a quarter of an hour. All three are fixed.**

### A browse session has its own end

There is now a **Close Browse Session** button beside Browse Files. It is lit only while an image
is actually open, so the button itself answers the question "am I still browsing something?".

Before this, pressing Browse Files a second time on an image you were already browsing silently
closed the session instead, and the only sign a session existed at all was a small `[browsing]`
note on the library row. Pressing Browse Files again now simply brings its File Explorer window
back, which costs nothing.

### Both ends state their cost before they start

Opening an image and closing it again each take minutes, and nothing used to say so. Measured on a
real 214 GB image: twelve and a half minutes to open. The reason is not the size. Windows builds
one placeholder for every file and folder in the image, one at a time on a single processor core,
and that image held 843,739 of them. **The cost follows the number of files, not how big the image
is**, so a small customer disk with a full Windows install on it is just as slow, and a faster disk
does not help.

TronForged now reads that count out of the image first, in a fraction of a second, and tells you
how many entries and roughly how long before anything begins. While it runs you see the real
progress the underlying tool reports, rather than one sentence that never changes. Once the image
is open, browsing it is instant.

### Closing the console no longer freezes it

Closing TronForged with a browse session open used to run the whole shutdown on the window's own
thread, so the window locked up with no explanation until it finished. It now asks, with three
answers: close the session now and watch it, exit now and leave it open, or do not exit at all.

Where there is nobody to answer - Windows is shutting down, the console is hidden, or it is a
customer console - it does not ask. It exits at once and leaves the session open rather than
holding up a shutdown behind a dialog box.

### A session left open is found again

A browse session left open, whether by that answer, a crash or a power cut, is listed in the image
library the next time you open the Imaging tab, and the same Close button ends it. Windows records
the open session even when TronForged is not running, which is what makes this possible.
TronForged never closes one by itself.

Two related repairs: a failed close is no longer recorded as a successful one, and the temporary
folder a session uses is now removed, but only after the close is confirmed to have worked.

### Worth knowing

None of this has run on real hardware, and the imaging tools as a whole still have not. Two
questions this release raised could not be answered here and are written into the bench plan by
name: whether a documented switch would cut that twelve minutes, and what a close actually costs
end to end.
