# v0.486.0 - TronForged 0.486.0 - Windows Server tab, cluster and headless remote desktop fixes

## TronForged 0.486.0 - Windows Server tab, cluster and headless remote desktop fixes

### A simpler Windows Server tab

- The Windows Server tab has a new layout. The top shows the server's name, its customer, its Windows version, how the
  page reaches it, and a label for each role it has (Domain controller, Hyper-V, Cluster member).
- The sections (Users, Groups, Computers, Virtual machines, Cluster, or Local users and Local groups) are listed down the
  left, each with how many items it has. Choosing a section lists it - there is no separate List button any more.
- Each section's items are shown in a table with plain columns, for example a user's name, full name and whether the
  account is enabled, disabled or locked. States are coloured: green when all is well, amber when something needs a
  look, red when something is broken or locked out.
- Typing in Search filters the table straight away. Press Enter to search the server itself, and Load more fetches the
  next page when there is one.
- The section's main action - New user, New group, or New VM on a cluster - is the one button above the table.
- Choose a row to see what you can do with it, as named buttons: for example Reset password, Unlock, Disable, Enable and
  Delete for a user, or Start, Shut down, Restart, Checkpoint, Export and Delete for a virtual machine.
- Each action opens a short form with a labelled box for every value it needs. Passwords are masked and yes/no choices are
  tick boxes. Enter sends the form and Esc closes it. The result is shown as one sentence.
- Actions that cannot be undone are shown in red, apart from the others, and ask you to type the item's name before
  anything happens. Deleting a VM still offers a backup first, ticked by default.
- The Cluster section opens with one line on the cluster's health, for example "CL-HV is running, but its witness is
  offline", followed by what that means and what to fix first. A healthy cluster gets one calm line that names its quorum
  and its shared volumes. Each node is shown as Up, Paused or Down with the number of virtual machines it runs.
- On a cluster member, clustered virtual machines and the server's own virtual machines are shown together, each with
  the actions that fit it.
- Internal action names and the free-text "name=value" box are gone; every action has a plain name.
- The same page opens in its own window from a server's row on the fleet.

### Windows Server clusters

- Installing Failover Clustering now runs on each server itself, through that server's own TronForged console. Before,
  one server tried to install it on the others, which fails unless that server is an administrator on them. For another
  server, open a remote session to it first (Remote in on its fleet row).
- A step that has to reach another server from the one you are on - the cluster check, creating a cluster, adding a node,
  shutting down, turning off, restarting or changing a VM that another node runs, deleting it, and moving a VM onto the
  cluster - now checks first that it can. If it cannot, nothing is changed and it says exactly what to do, for example
  "On SRV2, add CONTOSO\SRV1$ to the local Administrators group". The setup guide explains this prerequisite.
- Starting a clustered VM now goes through the cluster itself, so it works whichever node runs the VM.
- A cluster check in which a test failed is now reported as failed. Before, a failed test could show as a warning that
  could be ticked past. Creating a cluster and adding a node both refuse a failed check.
- If the check that runs just before Create finds warnings you had not read, Create stops and shows them. Ticking "I have
  read the warnings" covers only the warnings you saw.
- Removing a node now pauses it and moves its roles to the other nodes first, never removes the last node that is up, and
  stops if a role is still on it. Two new node actions: pause a node (its roles move off) and resume it (they move back).
- Adding a node runs the cluster check with the new node first and adds nothing when a test failed.
- Node actions now name the cluster, and destroying a cluster works only on the cluster of the server you are on and only
  once no virtual machine is left on it (the reply names any that are).
- Removing high availability from a VM now refuses anything that is not a virtual machine role.
- Turning a clustered VM off (pulling its power) now needs its name typed, like the other changes that cannot be undone.
- The cluster view now shows the quorum type, the witness and its state, and each Cluster Shared Volume with its state.
- The clustered VM list now says when a VM's details could not be read, and why, instead of showing empty values.
- Adding shared disks as Cluster Shared Volumes now skips disks that already are, carries on past a disk that fails, and
  says which disks were added and which failed and why.
- Node names typed with spaces around them are now accepted as the names themselves.
- The cluster wizard no longer says "not in the same domain" for a server that is simply not in a domain.

### Remote desktop on servers without a monitor

- Connecting to a Windows Server that has no monitor no longer shows a black screen that drops and reconnects every
  15 seconds. The connection now stays open while the server is answering, even when there is no picture to send.
- A reconnect to the same PC within 10 minutes no longer asks for a new 6-digit two-factor code. The first connection
  still asks for one, connecting to a different PC asks for its own code, and after 10 minutes from the code you entered
  you are asked again. Signing out, or a restart of the shop server, also ends the 10 minutes.
- A connection that finds the PC not waiting for you no longer uses up a code: the code is asked only once the PC is
  there. This applies to Temporary Fleet sessions too.
- When the screen on that PC is off or black, the Remote Desktop window now tells you so. When Windows reports that the
  PC has no screen at all, the window says that instead, and how to fix it.
- A server with no display output still needs a display emulator plug (a dummy plug), a monitor, or its management
  card's display turned on before Windows draws a screen to show. TronForged cannot show a picture Windows does not draw.
- If the TronForged console you connect to runs in a Remote Desktop session, the window now says so when the picture
  stops: Windows does not draw that session while its Remote Desktop window is closed. Sign in at the server, or sign
  out of that Remote Desktop session.
- A reconnect that brings no picture no longer restarts the 30-second reconnect allowance, so a connection that cannot
  show anything ends with its reason instead of trying forever.
- Not yet tried on a real server with no monitor at our bench: check the first headless servers you connect to.
