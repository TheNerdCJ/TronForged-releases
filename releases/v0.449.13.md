# v0.449.13 - TronForged 0.449.13 - Secure Data Erasure and Data Migration

TronForged 0.449.13 adds two new pages under **Data** on the technician console: **Secure Data Erasure** and
**Data Migration**. Update your shop server first.

**Not yet tested on real hardware:** firmware erase (ATA Secure Erase, NVMe Format and Sanitize) has not been run
on a real drive, and a real move between two PCs has not been run on a real network. Both have been tested only in
the lab with simulated drives and with both PCs on one machine. Try them on a spare drive and a spare pair of PCs
before you rely on them for a customer.

## Secure Data Erasure

The new **Secure Data Erasure** page erases drives so their data cannot be recovered, and writes a certificate for
each one.

- External drives (USB, FireWire, SD) are listed. You can erase an internal drive that is not the Windows drive
  after typing a second phrase, which the shop server records. The Windows drive, boot, system and recovery drives,
  the drive TronForged runs from, and backup or image-library drives are never offered.
- You type a phrase naming each drive. The drive is read again just before writing, and the erase is recorded on the
  shop server first. If either step fails, nothing is erased. The drive's volumes are locked and the drive is taken
  offline while it is written.
- 14 overwrite methods: Zero, Random, NIST 800-88 basic and advanced, Random & zero, current NSA, DoD 5200.28-M,
  AFSSI-5020, DoD 5220.22-M, NAVSO P-5239-26 (MFM and RLL), old NSA, German VSITR and Gutmann (with a time estimate
  first). Methods that define verification read the drive back, fully or by the sample the method names.
- SSDs and NVMe drives are checked for a firmware erase (ATA Secure Erase, NVMe Format or Sanitize). When the drive
  offers one, you can choose it, and it is reported as complete only when the drive confirms it. This has not yet
  been run on real hardware. An overwrite on an SSD is marked "may still hold recoverable data".
- Several drives are erased at once by default, each with progress, speed, time left and Stop. "One at a time" is a
  switch.
- A PDF certificate for each drive, under your shop's name, is saved and attached to the working ticket (shop only).
- A new **Erase drives** permission controls the page. Only Administrators have it until you grant it.
- A drive is matched by its disk ID as well as its serial number and size, so a swapped USB drive with no serial
  number is never erased by mistake.
- A drive that is being erased is shown as "Erasing now" and cannot be started a second time until its erase ends.
- The recovery drive that is protected is the one THIS Windows uses, wherever it is. An old PC's drive in a dock,
  with its own recovery partition, can still be erased.
- If a firmware Secure Erase stops early, the temporary drive password it set is always removed, so the drive is never
  left locked.
- NVMe Format is labelled as usually blocked by the Windows NVMe driver, so it is not offered as likely to work.
- An NVMe Sanitize waits for the drive to start reporting progress before it judges the result.
- If starting an erase fails, its drives are offered again straight away instead of staying "Erasing now".
- A recovery partition on an older MBR-style drive is protected the same way as one on a GPT drive.
- An overwrite erase has been run on a real USB drive: written, verified 100% and read back as zeros.
- The drive is checked again through the very handle that writes it: a drive that now reports no serial number, or a
  different MBR disk signature, is refused.
- If any volume on the drive cannot be locked or dismounted, nothing is written. A drive cache that will not confirm its
  writes stops the erase.
- If the certificate cannot be saved, the erase row says so instead of only "DONE".

The disk picker for restoring and cloning disk images, and the bootable-USB writer, now use the same protected-drive
rules as Secure Data Erasure. They work as before.

## Data Migration: move a customer to their new PC

The new **Data Migration** page moves a customer's files, settings and programs from their old PC to their new one,
over the shop's network or with a USB drive when there is no network.

- **Only your shop's PCs.** Both PCs must be enrolled to your shop server and signed in by a technician with the new
  **migration** permission. PCs that are not enrolled, or are enrolled to another shop, never appear.
- **You confirm which PC you are connecting to.** Press Discover on both PCs (it lasts 10 minutes). Pick the other
  PC, and both screens show the same 6-digit code and both PC names. Confirm on both. A code that does not match
  cancels the pairing.
- **Files and settings.** Choose folders (with their sizes) and settings: Wi-Fi networks, network printers, Chrome
  and Edge bookmarks, wallpaper and mapped drives. Settings are copied into the chosen user on the new PC.
- **Programs.** Each program is marked Good (reinstalled with winget), Average (a per-user app, copied) or Not
  supported (with the reason).
- **Safe transfer.** The new PC makes a restore point first. The transfer is encrypted, shows progress and time
  remaining, resumes after a dropped connection, and checks every file before it is kept. A temporary firewall rule
  on the new PC is removed when the transfer ends or after 10 minutes.
- **USB route.** Save an encrypted migration package on the old PC and load it on the new PC.
- **Both PCs must run this version** to migrate between them. The saved Wi-Fi passwords read from the old PC are
  deleted from both PCs as soon as the transfer (or the USB package) is finished. Cancel stops the transfer at once.
  A stray connection from another device on the network no longer ends the pairing, and a pairing left behind by a
  closed or crashed console clears when you press Discover again (or after a day).
- Data Migration now moves the customer's app settings and data (AppData) - program settings, browser profiles, email data and game saves - so reinstalled programs open the way the customer had them. Caches, temporary files and Windows' own per-PC folders are left behind.
- On the new PC, app settings are put in place after programs are reinstalled, so a fresh install can no longer overwrite them.
- The page names the apps whose saved passwords will not open on the new PC (Chrome, Edge, Outlook and others) and suggests syncing browser passwords to the customer's account first. Windows Credential Manager and similar stores are not copied; the customer signs in again.
- A file a running program holds open is skipped and listed, instead of stopping the whole migration. Close the customer's programs before you start.
- Programs moved by copy now carry the registry settings of the customer's own account, not the technician's.
- Pressing Cancel on one PC now stops the migration on the other PC too, which says "Cancelled on the other PC" instead of waiting and reporting a failure.
- A migration that is resuming after a dropped connection keeps its temporary firewall rule open for as long as it is waiting, instead of losing it 10 minutes after pairing.
- The new PC no longer gets stuck if another device on the network connects to it and sends nothing.
- If a migration stops part way (over the network or from a USB package), the page says how many items were already
  placed and which one stopped it, that a restore point was made, and where the items that had arrived were kept.
  Saved Wi-Fi passwords are never kept.

**For administrators:** when you update the shop server, every group that already has the **backup** permission
gets the **migration** permission too. Customer accounts never get it. New servers' Technicians group has it. You can
remove it from a group in Settings > Manage users.

## Licence

The licence gains two clauses: 11.6, Data destruction (Secure Data Erasure), and 13.5, Data Migration.

### Schedule (calendar)
- The Schedule page shows today at a glance: how many visits, the next one, and any double booking.
- A technician booked on two overlapping visits is now marked Double-booked on both, with who and which ticket.
- A visit whose reminder could not be sent says so on the calendar.
- New Book a visit button, and Add a visit on any visit to book a follow-up on the same ticket.
- "Cancel appointment" is now "Cancel visit", matching the ticket's own panel.
- A visit ending at exactly midnight no longer shows the next day's date.

### Settings (technician and customer consoles)
- The technician Settings page is reorganised into nine sections: My account, My screen, My defaults, Team chat, Shop devices, This PC, Report branding, About & updates and Danger zone.
- One Save settings button saves My defaults and Team chat; everything else applies as you use it, and each section says so.
- Safe Mode is one picker with Restart into it and Return to normal boot, and the page shows how this PC started.
- Prerequisites is now Required software (under This PC), and PawnIO is listed as the optional sensor driver.
- Report branding is shown read-only; change it in Server Console > Branding.
- Team chat no longer has a relay address or a passphrase box: it runs on the shop network and through your shop server, which manages the chat key.
- This PC (boot mode, required software, antivirus exception, catalogue reset) is hidden from profiles without remote access, and the Danger zone (repair, uninstall, disconnect, console role) is for administrators only.
- The signature pad test area no longer shows a bright white box in the dark theme.
- On a customer's PC, Updates is now the second card, and Force uninstall has its own Remove this program card at the bottom.

### Calendar
- You can book a visit straight from the calendar: click an empty time, pick the ticket, and set the time.
- Book a visit opens the same booking window, where you search open tickets by customer, ticket number or device.
- Drag a visit to another time or day to move it; you are asked before anything changes.
- Before a booking or a move that would double-book a technician, the calendar asks whether to go ahead.
- The same double-booking question is asked when a visit is added or moved from a ticket's own panel.
- Booking, moving and the calendar always use the shop's time zone from one place, so a visit is saved at the time the
  calendar showed.
