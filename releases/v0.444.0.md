# v0.444.0 - For the record only - unsaved server settings now say so (install v0.446.0)

Published for the record after v0.446.0. Install the latest release instead: it includes everything here and later fixes.

**This release is published for the record only.** It is not offered as an update: shop servers, consoles and new installs never receive it. Install v0.446.0 or later instead - it carries everything below plus fixes to it, and its release notes cover v0.443.0 through v0.446.0.

What v0.444.0 added, on top of v0.443.0's tray alerts:

- **A setting the shop server could not write to disk says so.** A settings change is used by the server straight away, but it survives a restart only once it has been written to disk. The **Square** page (and **Pair a Terminal...**), the **Email** page, the shop's default backup quota and the backup storage location used to report success even when that write failed, so a Square token or mailbox password that never reached the disk was gone at the next restart. The Server Console now says when the server is using a change but could not write it to disk, and the audit log marks such a change *[NOT SAVED TO DISK]*.
- **Dynamic DNS and the release feed** also warn when the part that could not be written was a token, which the server keeps in a separate file from its other settings.
- The warnings need the Server Console and the shop server both on this release.

Do not install this version. Problems found in it are fixed in later releases. Among them: while a technician is signed in on a customer's PC with **Technician sign-in...**, that PC can show tray alerts naming other customers and their tickets (fixed in v0.445.0); the AI settings page can show a change as failed when it was made (fixed in v0.446.0); and a technician console that has started a remote-control session stops installing its own updates when idle (fixed in v0.446.0).
