# TronForged v0.487.0

Remote desktop sends less when you scroll or drag a window, and the customer's pointer can now be shown
before anyone signs in wherever Desktop Duplication capture is in use.

## Remote desktop

- **Scrolling and dragging windows cost far less.** Where the full-control helper captures with Desktop
  Duplication (the default since v0.449.19, when it works on that PC), Windows tells TronForged
  when part of the screen simply moved (a page scrolled, a window dragged). That part is now sent as a short "move this area" instruction, and your viewer moves the picture
  it already has, instead of the whole area being compressed and sent again. Only what actually
  changed is sent. In our tests a scrolled page cost about one twentieth of the data per frame, and
  a dragged window well under half. The picture you see is the same as before.
- **The customer's pointer before sign-in.** Your viewer has shown the customer's mouse pointer
  since v0.463.0, but only when the TronForged console on that PC could read it. When the
  full-control helper is the one showing you the screen (before anyone signs in) and it is capturing
  with Desktop Duplication, the helper now sends the pointer's position, and its shape once
  each time the shape changes. Your viewer draws it on top of the picture.
- **Nothing changes when either end is older.** Both improvements are used only when your console
  and the helper on the customer's PC are both v0.487.0 or newer. An older viewer, an older console
  or an older helper keeps working exactly as before.
- **Nothing changes where the standard capture is used.** The pointer and the move instructions come
  from Desktop Duplication. Where the helper uses the standard (GDI) capture instead - Desktop
  Duplication failed its self-test on that PC, or "deskCapture": "gdi" is set - and on the Windows
  sign-in and UAC screens, which always use the standard capture, remote desktop works exactly as it
  did in v0.486.0.

## Known limits

- The before-sign-in pointer needs Desktop Duplication, so it is not shown on the sign-in screen or
  a UAC prompt itself.
- Neither improvement has been tried yet on real customer hardware.
