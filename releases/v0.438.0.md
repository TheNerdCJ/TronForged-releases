# v0.438.0 - One working ticket for every job, and a Service Desk that keeps up

This release brings seven updates together (v0.432.0 to v0.438.0), and it changes both the shop server and the consoles. The biggest change is how work reaches a ticket. The ticket you choose in the Service Desk with **Log my work here** is now the one ticket for the work you do on that PC. Service runs, single stages, fixes, QC checklists, data recovery reports and customer summaries are recorded on it or attach to it by themselves. You can no longer type a ticket number on the Automated Service tab. The Reports tab's Customer Reports and Job History lists are gone, because a run's reports now live on its ticket. The Service Desk no longer freezes while an AI brief or draft is being written, and after each action it now says what actually happened. Two people editing the same customer no longer undo each other's changes, customer names must be unique, and the RepairShopr import now creates customers. When Ctrl+Alt+Delete cannot be sent to a remote PC, the message says why.

### Service Desk and tickets

- **One working ticket.** Open a ticket and click **Log my work here**. It becomes this PC's working ticket: the title bar names it on every tab, and the button changes to **Logging work here** (click it again to stop). The Automated Service tab's **TICKET** box shows it, and you can no longer type in that box. The button beside the box says **Choose in Service Desk**, or **Change in Service Desk** once a ticket is chosen, and takes you to the Service Desk. The customer name also comes from the ticket, and you cannot type over it while a ticket is chosen.
- Only an open ticket can be chosen. If the working ticket is resolved or closed, by you or by anyone else, the Service Desk says so and it stops being the working ticket. A technician who signs in on a customer's PC and then signs out also clears the working ticket they chose there.
- **Two new questions when you start a run.** When no working ticket is chosen, **Start Service** and a single stage on the Manual Stages tab now ask "Start without a ticket?". When the ticket is linked to a different computer, they ask "Run here anyway?". Both default to No, and No starts nothing.
- **What attaches to the ticket, and who can see it.** When a run finishes, its service report (or stage report) attaches to the working ticket, where the customer can see it. These attach as shop-only files, which the customer cannot see: the run's receipt, a QC checklist (**Save QC Report**), a data recovery report (**Save Report** on the Data Recovery tab) and an approved customer summary. The ticket's **Files** list marks them *internal*. To give the customer one of them, save it from the ticket's **Files**, then attach it again with *Visible to the customer* ticked.
- If the ticket was resolved or closed while the run was going, the report is not attached at all. The run's log says so, and the file stays on the PC. Shop-only files still attach, and the message tells you the ticket's status.
- **A run that restarts the PC** (a Safe Mode scan, or Windows updates) says so, and its work record shows that it restarted the PC to carry on. Its final report does not attach by itself, and it is not listed under the ticket's *On this PC*. Find it with Reports > **Open Reports Folder** and add it with **Attach a file...** in the ticket's **Files**. Tick *Visible to the customer* if the customer should see it.
- **Open Report** now opens the run's own report, the same file that was attached to the ticket. It used to open the newest report on the PC.
- A run without a ticket no longer prints "Ticket #: NO-TICKET" on its report and receipt.
- A work record now says when a technician stopped a run early or used Emergency Stop, and when a run restarted the PC to carry on. If a work record does not reach the server, a notice in the Windows notification area now says so too.
- **Choose the ticket before data recovery.** Each recovery step belongs to the working ticket chosen when the step ran, and a data recovery report lists only that ticket's steps. Steps done before you chose the ticket are left out of its report.
- **No more freezing while AI works.** While a ticket brief or an AI draft is being written, the Service Desk keeps refreshing, and replies, status changes and chat keep going. This needs the shop server on this release too (see *After you update*). The console also waits as long as the slowest AI answer can take, so it no longer gives up on an answer your shop has already paid for.
- Each console connection can run 2 AI requests at once, and the server 8 in total. A request beyond that is not queued. It is turned away at once, with a message saying the console or the server is busy.
- **Brief this ticket**, **Draft a reply with AI** and **Rewrite with AI** now appear only while that AI feature is switched on for your shop.
- **A ticket cannot be resolved twice.** Each resolution sends the customer a message. The server now refuses to resolve a ticket that is already resolved, or that was resolved and then closed, and the message suggests replying to the ticket instead. To resolve it again, set it back to open first.
- After you resolve a ticket, link a machine or set a ready-by time, the ticket is reloaded from the server, so it shows what was actually saved.
- The message strip at the top of the Service Desk now keeps an action's message until you click **Dismiss**. A background refresh no longer overwrites it.
- An AI brief or draft that arrives after the ticket has refreshed is kept for that ticket. It never appears on another ticket, and it never replaces text you typed while you were waiting.
- Ticket numbers on the *Needs attention today* card now open that ticket, for accounts that are allowed to open tickets.
- Printing an invoice no longer freezes the console while it looks up the ticket.
- Searching the ticket and invoice lists by surname now finds a customer whose surname is only in the Last name field.

### Customers

- **Two people editing one customer no longer undo each other's changes.** Saving a customer from the Service Desk, from Customers & fleet or from the RepairShopr import now sends only the fields that changed. A save from a window opened earlier no longer puts back what someone else changed in the meantime - with one exception: the customer's **name** is always saved, so a window opened before someone else renamed the customer puts the old name back. If a customer may have been renamed, reopen it before you save. This works once everyone doing the editing is on this release.
- If the server shortens a field because it was too long, or does not store it as typed, the save now tells you which field.
- **Customer names are unique.** Two customers' names must now differ by more than capital letters or spaces at the start or end. Adding a customer, or renaming one, to such a name is refused. The message names the other customer and suggests adding something to tell them apart, such as the street. If you already have two customers whose names differ only in capital letters, you can still edit them as long as you do not change the name.
- The person to ask for (the first and last name on the record, or the contact name on older records) now appears on the printed invoice's Attn line, on the Service Desk's customer card and on the Customers & fleet page.
- Invoice emails now greet the person on the record by first name. A business with no person on file is greeted with "Hello," instead of the first word of the company name.
- A login linked to a customer, such as a customer's own account, can no longer edit your customer records. This applies even if the login was put in a staff group by mistake.
- **The RepairShopr import now creates customers.** Until now, importing a RepairShopr customers export from the Server Console never created a new customer. If you tried it before, run it again once your server is on this release. Importing the same export again updates the customers it created. Anything the export does not contain is kept: an extension or customer type you set by hand stays, and phone numbers are added rather than replaced. A value the export does contain, such as a name, email address or street address, replaces what is on file, including a correction you made by hand. Make lasting corrections in RepairShopr too. The import reads your server's customer list first and sends nothing if it cannot. When it finishes, it tells you how many customers were new, updated and failed, and shows the first error.
- A row fails if the export contains two customers with the same name, or a customer with the same name as one you already have. The finish message names only the first failure, so when several rows fail, look for names the export shares with itself or with your existing customers. To bring such a row in, give one of the two a different name (in RepairShopr, or on your existing customer), export again if you changed RepairShopr, and import again.

### Remote support

- **Ctrl+Alt+Delete says why it could not be sent.** It used to always say that the full-control helper needed installing, even when the helper was installed. Now it gives the actual reason:
  - the helper is not installed;
  - it is installed but too old for this command (the message gives its version);
  - it is installed but not running;
  - it failed the check that it is the real helper;
  - it did not answer in time.

  If the helper is **not installed** or **not running**, install it on that PC: in the viewer, click **Enable UAC / lock-screen control**, or on the PC itself open **Settings** and click **Install helper** under *Full-control helper* (on a customer's PC, sign in there as a technician first - a customer's own Settings do not show it).

  If the helper is **too old**, **Install helper does not fix it**, whatever the message says: it registers the same old file again. Restart TronForged on that PC, or restart the PC, so the update can replace the helper file. Then end the remote session and connect again, because once Ctrl+Alt+Delete has failed this way it stays off until the next session.
- A slow answer no longer switches Ctrl+Alt+Delete off for the rest of the session. The next press tries again.
- Both Ctrl+Alt+Delete changes happen on the customer's PC, so you see them only once that PC has this update.
- Runs and fixes you start from the Remote tab's **REMOTE CONTROL** panel are not recorded on any ticket's work record, including your own working ticket. A service run started there still attaches its report to the ticket number typed in that panel. Before this release, those runs and fixes were recorded on whatever ticket had been chosen on the PC at the other end, which you could not see from your side.
- The ticket and customer you set in the remote control panel no longer overwrite the ticket and customer boxes on the far PC. They are also cleared when the last viewer disconnects, so the next session does not start with the previous job's ticket already filled in.

### Reports

- **The Reports tab's Customer Reports and Job History lists are retired.** The tab now holds only the device reports (battery, storage, system summary and so on), and **Open Reports Folder** is still there.
- To find a run's reports, open its ticket in the Service Desk and look under **Files**. On a customer's own PC, which has no Service Desk, the reports are in the reports folder: Reports > **Open Reports Folder**. The **On this PC** section lists the reports that runs for that ticket saved on this PC, each with **Open** and **Draft customer summary**.
- **Draft customer summary** is also in the footer beside **Open Report**, for the run you just finished. Approving a summary inserts it into the report on this PC as before. It now also attaches the summary to that run's ticket as a shop-only file. The copy of the report already on the ticket does not change, so the customer does not see the summary until you share it.
- A draft customer summary from an updated console no longer sends the customer's name, the ticket number or the report's location to the AI provider. The licence (sections 11.2 and 15.2) now describes this, and it also describes what attaches to a ticket and who can see it.
- *On this PC* does not list reports from runs made before this update, or from runs without a ticket. You can no longer draft a customer summary for those reports, except from the footer just after the run. They are still in the reports folder on that PC (Reports > **Open Reports Folder**), and so is the job history file.

### Server

- An AI request no longer holds up everything else on a console's connection to the server. That is what keeps the Service Desk working during a brief or a draft.
- If your shop uses Claude Code on the server box instead of an API key, an AI request that stalls is now always stopped at its time limit.
- **A PC that changes hands no longer shows the previous customer's tickets.** You might move a PC to another customer on Customers & fleet, or it might go back to walk-in. Either way, the previous customer's tickets that named that PC disappear from its *Messages from your shop* window. The next person at that PC can neither read them nor reply to them. The Service Desk keeps the link as that machine's history.
- A ticket that a customer opens from *My shop account* on their own PC is now linked to that PC automatically, as long as the PC is filed under that customer. A customer with more than one PC therefore sees that ticket in *Messages from your shop* only on the PC they opened it from. *My shop account* still lists all of their tickets.

### Before you update

- Tell your technicians that the ticket number can no longer be typed on the Automated Service tab. They choose the ticket with **Log my work here** in the Service Desk. A run started on the PC itself now prints the Service Desk ticket's number on its report and receipt, so a number from another system can no longer be put there. An account that is not allowed to manage tickets in the Service Desk cannot choose a ticket. Its runs start only after someone answers Yes to "Start without a ticket?", and they are not recorded on or attached to any ticket.
- If your staff use the Customer Reports or Job History lists, show them where those reports are now (see *Reports* above).

### After you update

- **Update the shop server too.** Your consoles update from your server as usual, and the server updates its own program when the shop is quiet. Several changes in this release work only once the server itself is on it:
  - the Service Desk not freezing during AI, the AI limits of 2 and 8, and the time limit for Claude Code;
  - refusing a second resolve;
  - hiding a previous customer's tickets from a PC that changed hands, and linking a customer's ticket to their PC;
  - unique customer names, and the RepairShopr import creating customers;
  - blocking customer logins from editing customers;
  - the invoice email greeting, and the warnings about shortened fields.

- **Run the RepairShopr import only from a Server Console that has this update.** Once your server is updated, an older Server Console's import can create the customers too, but importing again from that older console overwrites every change your shop made to them.

  To update now, open the Server Console on the server, go to **Settings** and click **Update everything on this PC** (under *Updates for this PC*). The server stops for about a minute, and this update does not change the structure of your shop's database. Until the server is updated, an updated console works with it as before, and the Service Desk still waits while an AI request runs.

### Known issues

- **Stop Safely can be pushed off the screen in a narrow window.** The new **Draft customer summary** button makes the row of buttons at the bottom wider. If the console window is narrower than about 780 pixels (for example, snapped to half of a small screen), **Stop Safely** can fall off the left edge while a run is going. Widen or maximize the console window before you start a run.
- **Choose machine... on a ticket cannot link a machine yet.** It answers *No such machine.* A ticket that a customer opens from their own PC is still linked to that PC automatically, so the *Run here anyway?* question protects those tickets; a ticket booked at the counter is not linked to a machine.
- **An update can restart the console during a long Data Recovery job.** When an update is waiting, the console restarts itself to install it after 10 minutes without mouse or keyboard input, and shows a 60-second countdown with a **Not now (1 hour)** button first. The restart stops a Data Recovery image, carve or analysis that is still running. Before you leave a long recovery job running, install any waiting update first, or press **Not now (1 hour)** when the countdown appears.
