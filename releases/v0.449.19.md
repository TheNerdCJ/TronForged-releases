# v0.449.19 - TronForged 0.449.19 - PC transfer from a dead PC's drive, the shop's app cache, lighter consoles

## TronForged 0.449.19 - PC transfer moves programs from a dead PC's drive, and the shop's app cache

### Data Migration

- **Programs from the old PC's drive.** When the old PC will not start and its drive is connected to the new PC, TronForged now reads the programs the old PC had, finds them in winget and installs them on the new PC during the transfer - then puts back each program's own settings and the customer's app data, so the programs open the way the customer left them. Each program is marked Good (installed with winget), Average (a per-user app copied with its settings) or Not supported, with the reason. When winget has more than one package a program could be, you pick it - nothing is guessed.
- **A program's settings travel with it.** Each program's app-data folders now move with it even when the whole "App settings and data" row is unticked.
- **The new PC gets a user for the customer.** When the new PC has no user with the old user's name, Move from this drive offers to create one (a local account, an administrator unless you untick it, and with no password until the customer chooses one at the first sign-in). "Create a user on this PC..." does the same for any route. Each creation is recorded in the shop server's audit log.
- **Printers and mapped drives now come from the old drive too**, and the summary lists the Wi-Fi networks the old PC knew, so you know which to join again (their passwords cannot move).
- **Fixed:** on the old PC, a user who was not signed in had their own programs, program settings, printers and mapped drives silently left off the lists. They are now read from that user's own registry file.
- **Fixed:** two PCs in Discover that could not see each other were given no reason. Now the screen says why: the other PC chose the same role (it is named - choose Old PC on one and New PC on the other), the other PC is already paired, or no other PC is discovering on this shop server (check both are signed in to the same server). It also shows the name this PC appears under on the other PC. Update the shop server too for the named reasons.
- **Fixed:** a second migration in the same console no longer repeats the first one's lines in its summary and saved report, and a report from a drive names the drive and this PC.

### The shop's app cache

- When a PC on the shop's network installs or updates an app (Apps page, Data Migration) or downloads an ISO (ISO Files tab), the shop server keeps a copy, and the shop's other PCs get it from the server instead of the internet.
- Only the newest version of each app or ISO is kept; the older one is deleted when a newer one arrives.
- Only PCs on the shop server's own network are served. A PC at home or over the internet downloads from the internet as before.
- Nothing cached is used unless it is exactly what that PC would have downloaded itself: an installer must match the hash winget publishes for it, and an ISO must be the release its source serves now (and, for Ubuntu, Linux Mint and Kali, match the published SHA-256 list - internet downloads are now checked against that list too).
- The cache lives in its own folder on the server (by default <server data>\appcache), never in the backups folder. See SERVER_SETUP.md to move it or change its size.

### Lighter on every PC

- **Remote desktop uses less.** The technician's screen now redraws only what changed on the customer's screen, instead of the whole picture for every update. A session keeps to a bandwidth budget that follows the customer's connection (about 8 Mbit/s at most, and about 70% of what the line carries), so a video or a big scroll lowers the frame rate instead of filling the customer's upload. A still screen re-sends its full picture every 5 minutes instead of every minute.
- **Cheaper screen capture.** The full-control helper now uses DirectX Desktop Duplication by default where it works (one monitor, the normal desktop, after a self-test), and passes tiles to the console as raw bytes instead of text. Set "deskCapture": "gdi" in a console's gui.json to turn Desktop Duplication off.
- **Quieter when hidden.** A Server Console sitting in the tray no longer reads every hardware sensor (including every disk's SMART data) and the server every 15 seconds; the Service Desk stops refreshing while hidden; the performance strip asks for GPU use every 5 seconds and slows down when the window is in the background; the error and maintenance logs are capped at 2 MB.

### What to do

- Update the shop server to this version to use the app cache and to record user creation and drive moves in the audit log. Consoles work as before against an older server.
- Not yet tested on real hardware: a real dead PC's drive, account creation, installs from the cache, and Desktop Duplication as the default.
