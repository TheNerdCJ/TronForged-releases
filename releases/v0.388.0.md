## v0.388.0 - Windows Fixes tell you what they actually did

A fix used to report "Applied" whenever it finished without crashing - which a script can do
while every step inside it failed. This release replaces that with what was actually
observed.

**What you will see now.** A fix says:

- **"Fixed:"** only when it carries a check that was false before it ran and true afterwards.
- **"Already correct"** when that check was already true - nothing needed changing.
- **"NOT fixed"** when the check still fails afterwards, including when the fix itself
  printed nothing. That last case used to be indistinguishable from success.
- **"finished, but reported a problem: ..."** quoting the machine's own words, so you can
  judge it in a second. This is not a failure - most often it means the thing being cleaned
  up was not there.
- **"stopped part-way"**, **"did not finish"** (it was stopped after 15 minutes), or
  **"finished, reported nothing"** - which is a statement about the run, not a claim that
  anything changed, and says so.

**Fifteen fixes now check their own work** - re-enabling Task Manager, the Registry Editor
and the Command Prompt, clearing print queues, rebuilding the Outlook cache, and others.

**Other improvements.** A fix that hangs or waits for input is now stopped after 15 minutes
instead of leaving the button stuck on "Working..." forever. Every fix run is recorded in
`logs\fixes.log` with its result and the first error line, so a fix that behaved oddly last
Tuesday can still be looked up.
