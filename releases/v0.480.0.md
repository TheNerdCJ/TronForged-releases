# v0.480.0 - TronForged 0.480.0 - Temporary Fleet: on by default, switched from the Server Console, several sessions at once

## TronForged 0.480.0 - Temporary Fleet: on by default, switched from the Server Console, several sessions at once

### Temporary Fleet is on whenever the web transport is set up
Temporary Fleet (the customer's PIN page and the one-time support download) is now **on by
default whenever the shop server's web transport (WSS) is set up** - it has a certificate and is
listening. Without the web transport it stays off, because the PIN page cannot be served.

**What this means when you upgrade:** if your server never turned Temporary Fleet on or off and
its web transport is set up, upgrading to 0.480.0 turns Temporary Fleet ON. The PIN page then
answers on your shop's web address. If you do not want that, untick Temporary Fleet in the Server
Console after upgrading; that choice is saved and stays off. A server that had it turned on keeps
it on.

### The switch is in the Server Console
The on/off switch has moved from the Technician console's Temporary Fleet page to the Server
Console's Status page, under the Web transport (WSS) row. It needs administrator rights, and from
a PC other than the server also the server-administration permission, as before. When the web
transport is not set up the switch is greyed out with a one-line reason.

The Technician console's Temporary Fleet page works as before and now shows a read-only line:
"Temporary Fleet is on - change it in the Server Console's settings." (or off).

### Several temporary sessions at once
One technician can now run several Temporary Fleet sessions at the same time. Start a session for
each customer and press **Connect** on each row once that customer is waiting; every connected PC
opens in its own Remote Desktop window. Connecting to the same PC twice is still refused.

**Install TronForged on this PC** now goes to that row's PC only, never to whichever window was in
front.

### Temporary sessions per technician is a setting
How many temporary sessions one technician may have open at once used to be fixed at 5. It is now
a server setting: Server Console -> Settings -> Temporary Fleet -> **Temporary sessions per
technician**, a whole number from 1 to 50 (default 5). It needs administrator rights. If a save
does not reach the server, the page says so.

### Reconnecting after a dropped connection
We checked that the customer's support program reconnects by itself when the technician's side
drops for a moment, and that the session stays open past the two-minute grace period. No change
was needed.

### A clearer PIN page for your customer
The page your customer opens to enter the PIN has been redesigned: the PIN goes into six separate
boxes, the page shows which step the customer is on, a mistake is explained in a clear panel, and
the page follows the customer's light or dark setting. The one-time support download is now named
Support-<PIN>.exe, shorter and easier to find in the Downloads folder.

### Invite a second technician
The technician in control of a remote session can now bring in one colleague: press **Invite technician...** in the Remote Desktop window and pick a name. The colleague gets a join card on their console, valid for 5 minutes and usable once. The customer is asked separately about each technician, and refusing one does not end the session with the other.

The colleague watches read-only, with a new picture every 2 seconds, until handed control with **Give control to...**. Everyone, including the customer, sees who is watching and who is in control. If the technician in control leaves, control returns to whoever started the session, or otherwise to whoever has been connected longest.

### Square: invoices and pasted tokens are gone
**Square invoices are gone.** TronForged no longer sends invoices through Square: "Invoices through Square", Send via Square and Send selected to Square have been removed. Invoice from TronForged as normal and take the money with a pay link or a Terminal charge; a pay link paid at Square marks the TronForged invoice paid. A Square invoice still open when you upgrade is listed once on the Server Console for you to record by hand, and is no longer followed.

**Pasted Square access tokens are gone.** Connect with Square is now the only way to connect. A server already on a pasted token keeps working until it is disconnected, and the page tells you to reconnect.

### Other Square changes
- Connect with Square asks only for the permissions of the jobs you have switched on. Switching on another job later may ask you to reconnect.
- A renewed Square connection is saved before it is used. If it cannot be saved, the Server Console says "Square needs reconnecting".
- A very old pay link Square could not be matched to a payment is listed once for you to record by hand, and closed.
