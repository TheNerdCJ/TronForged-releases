# v0.449.15 - TronForged 0.449.15 - updates no longer get stuck or crash

## TronForged 0.449.15 - updates no longer get stuck

An urgent fix release. Some PCs stayed on an old version for days because their update could not be put in place, and the shop server held the new version back from every other PC while that happened.

### Fixed

- **Updating no longer crashes the version being replaced.** TronForged is one self-contained program file. A copy that is already running keeps reading parts of itself from that file. When an update replaced the file, a running copy could crash with "TronForged could not unpack its files." Each copy now loads everything it needs when it starts, so an update can safely replace the file underneath it. Copies older than 0.449.15 can still show this message once while they are replaced. Click OK and start TronForged again, and it runs the new version.
- **An update is no longer blocked by a console that was left open.** When a TronForged window had been open since the previous update, the program file from that update was still in use and could not be removed. Every later update was then refused until the PC restarted. The update now moves that file out of the way and goes ahead, and the file is cleaned up after the window closes.
- **The shop server now says why a PC's update failed.** Each PC already sent its reason with its update report, but the server stored it without showing it. The reason now appears in the audit log next to the failed update, and in the line that says a release is held back.
- **No more false warning after a helper update.** The full-control helper was replaced and checked correctly, but `agent-service.log` still said one of its files "could not be written". That line is gone.

### What to do

- A PC that is still on an old version may need **one restart** to take this update. After that, open windows no longer block updates.
- If the audit log shows "could not find its own TronForged program to replace" for a PC, reinstall TronForged on that PC.
