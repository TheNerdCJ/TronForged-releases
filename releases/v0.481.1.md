# v0.481.1 - TronForged 0.481.1 - Faster connections from outside the shop

## TronForged 0.481.1 - Faster connections from outside the shop

### Adding a new PC from a customer's home

When a new PC asks to join your shop from outside the building, it now tries the port you gave it and your server's web transport at the same time, and uses whichever answers first. If your shop's address goes through a proxy such as Cloudflare, the PC no longer waits out a port the proxy does not carry: it connects in about a second instead of more than a minute. Once the web transport has answered, a port that only went silent is not tried again.

The "This internet connection is very slow" message now appears only when the web transport was slow as well, not just because the port you typed got no answer.

### Enrolled PCs reconnect faster

An enrolled PC now tries all of your server's routes at once (the local address, the public address, the last-known direct address and the web transport) and uses the first that answers. When two answer together it still prefers the direct ones, as before. It remembers the route that worked, so the next time it starts it tries that one first. If a remembered route stops working, it is forgotten and every route is tried again.

### One-time support and downloads

The one-time support program gives up on a wrong or unreachable address after 6 seconds instead of 15. Secure connections to your shop server, and the product's downloads, now check whether a certificate has been revoked using the information Windows already keeps, instead of contacting the certificate authority during every first connection. A certificate known to be revoked, untrusted, expired or issued for another name is still refused.

### Automatic maintenance

- A scheduled maintenance run never restarts your PC and never switches it into Safe Mode, whatever its profile says. If Windows still needs a restart, it waits for your next normal restart.
- A run you missed (the PC was off or asleep) is caught up only after the PC has been idle for 15 minutes, and a scheduled run is put off when someone used the PC in the last 15 minutes. Run maintenance now is never put off.
- Each scheduled run starts at a random time up to an hour after its set time, so a whole fleet does not start at once.
- A run that goes on too long is stopped after 3 hours 45 minutes, together with every program it started.
- When Windows' app installer (winget) is busy, the run waits up to about ten minutes before it gives up.
- Every run that is put off, refused, stopped or fails is now recorded for your shop, and the technician's fleet view shows each PC's maintenance schedule and how its last run ended.
- The maintenance page now also says whether the schedule catches up a missed run.
- The schedule is Monthly or Weekly. Daily is no longer offered; an existing daily schedule keeps running until you press Apply schedule.
- The maintenance profile no longer empties the Recycle Bin, clears browsing history or optimizes drives (Windows does that itself), and it runs the deeper DISM repair only when the system file check finds damaged files.
- After updating, press Apply schedule once on the Maintenance page so an existing schedule gets the new settings.

### Service report improvements

- If a service is stopped before it finishes, the report now says so at the top and lists the parts that did not run.
- The PDF copy of the report no longer prints the browser's file path and date in its margins.
- Every report, receipt and run record is named for its own service run, so two walk-in services done at the same time never overwrite each other.
- Folder names and paths that could include a person's user name are hidden in the report's details and drive names, and the receipt shows the name of the computer that was serviced.
- The PDF, your run record and (on laptops) the battery report are now attached to your ticket where you can see them, alongside the report.
- When your technician adds a written summary to the report, the PDF and the copy on your ticket are updated to include it.
- The run record page now looks like the report, with the shop's name and logo, plain step names, and an honest reason for each skipped step.
- The number of threats removed is the same on the report, the receipt and the run record.
- Sizes that were not measured say "not measured", a drop in free space is explained, very short steps show "<1 min", and the report shows when the service started and finished.
- A "Still needs attention" list replaces the old "See notes" mark, and the receipt no longer shows empty lines.
- Each report now opens with three plain lines: what was found, what was fixed, and what still needs attention.

### Faster disk images

Sending a disk image to your shop server does less work for the same result:

- **Several pieces travel at once.** The console now keeps up to eight pieces of an image in flight to the server instead of waiting for each one to be answered, and each piece is twice as large (6 MB). The server stores them side by side and still checks the whole image against what the console sent before it marks it complete.
- **No second full read after a capture.** When you capture straight to the Shop server, the image is no longer read from start to end a second time before it is sent. The capture already fingerprints every part as it writes it; the upload now checks each part against that fingerprint as it sends it, and if any part does not match, nothing is stored and the upload is removed. Images that stay on a drive here are still checked in full, as before.
- **A dropped upload resumes straight away.** Resuming an interrupted upload no longer re-reads the part the server already has, so it picks up where it stopped instead of reading the whole image again first.
- **No slow-down on your shop network.** Upload pacing, which protects a customer's slow internet connection, no longer applies when the console is on the same local network as the server. It also no longer mistakes a busy server disk for a busy connection.
- **Images are not compressed a second time on the wire.** A disk image is already compressed, so the console no longer spends time trying to compress it again.
- **Smaller backups on the server's disk.** The server now stores each piece of a backup in about 55% of the space it took before. Backups stored by earlier versions stay exactly as they are and restore as before.
- **One snapshot moment for every drive.** When a capture includes extra data drives, their snapshots are now taken at the start together with the Windows drive's, so the whole image reflects the same moment.

Consoles and servers from before this release keep working with each other and with this release: a new console sends to an older server one piece at a time, as before, and an older console works with a new server unchanged.
