# v0.448.1 - v0.448.1: the code-only security Highs - forensics, disk images, downloaded tools, and the shop server's folders and log

This release follows v0.447.1, and these notes cover everything that changed since then. (Version 0.448.0 was never released; everything it contained is in this release, with the corrections below.) If your shop server has not taken v0.447.1 yet, read the v0.447.1 release notes too: everything in them applies to this update as well.

This is a security release. In short:

- **Forensic evidence is collected into a folder only the PC's administrators can open**, by default on a removable or second drive rather than the PC's own system drive, after a consent that says who can read it. Your shop server signs the fingerprints of each collection, and only that signed record is attached to the ticket.
- **Disk images are locked to the PC's administrators** where the drive allows it. New images no longer go under the Program Files folder by default, images older than 90 days are flagged for review (never deleted), and uninstalling TronForged keeps your image folders.
- **Every tool TronForged downloads is checked before it is kept and again before it runs**: its fingerprint must match the one this release carries, or it must be signed by that exact vendor. A few tools are now shown as their vendor's page instead, and TronForged does not download those at all.
- **The shop server locks its own folders, keeps its own log for 90 days, and says on its Status page** when a folder is open, where its log is, and what it found of the old PostgreSQL folders and old database copies.
- **Scripts TronForged writes and runs as administrator carry no data of yours**, and are written into a protected folder.

This release updates the consoles and the shop server's program. It does not change the structure of your shop's database. The licence changes too - see **The licence** below.

### Before you let your shop server take this update

- **If your shop server is older than v0.447.1**, do the steps in the v0.447.1 release notes first.
- **If you set up your shop server from a server program you built yourself** (rather than one downloaded from our releases), the installer now deploys a server program only when its fingerprint matches the one we publish for that version, or one you pinned. Before you reinstall or update from your own build, copy the SHA-256 fingerprint the build prints into `serverExeSha256` in the `config\server-setup.json` file (edit it from an editor run as administrator). There is no box to type it into. The same applies to a server program from our releases that you picked by browsing to the file: the installer checks it against the fingerprint our release feed publishes, so the server PC must be able to reach the release feed at that moment - or you pin its SHA-256 the same way.
- **Do not run a port forwarder or tunnel on the server PC itself** (for example cloudflared, `netsh portproxy` or IIS/ARR in front of the server's ports). Forward to the server PC from another box or your router instead. The server's setup guide says why.
- **Plan to update the shop server first, by hand**, before your other PCs take this release (see **After you update**). Several of the changes below need both sides on this release - see **Mixing versions**. This matters most if your shop relies on tools it added itself: a console on this release runs a shop's own tool only after its fingerprint is recorded on the shop server, and an older server cannot record it.

### After you update

- **Update the shop server by hand as soon as you can:** on the server PC, **Server Console > Settings > Updates for this PC > Update everything on this PC**. Then bring the Server Console on the server PC to this release too (**Settings > Console updates**, as in the v0.447.1 notes); the console update finishes when you press **Restart now to finish**.
- **Then, from that Server Console on this release, run Set up server > Update server once.** That locks the server's own folders and puts their permissions back without wiping anything. Do NOT use **Reinstall server...** for this: a reinstall is a factory reset that wipes the server's data. Until Update server has run, the Status page may say a server folder is open (see **The shop server**).
- **If your shop server ever ran on PostgreSQL, lock its old folders.** In the Server Console, go to **Set up server > Database engine** and press **Lock the old PostgreSQL folders...**, then check that the Status page still reads the server as healthy. (The Status page tells you when those folders are still there.) Until you do, those folders stay readable by every account on the server PC, and they keep any card number typed before the move to the embedded database. After 14 days on the embedded database, the Status page and the Database engine page offer **Retire PostgreSQL...**, which deletes them only when you type the confirmation.
- **If this shop uses the Claude Code AI option, deploy the Claude CLI again** - from a Server Console on this release: **Server Console > Settings > AI features**, with **Claude Code on this server box (your Claude subscription)** chosen, press **Deploy the CLI for the service...**. Every copy deployed before this release is refused until it is deployed again, and the AI page says so in red.
- **Lock your existing image folders.** Image folders that already exist stay readable by every account on that PC until you lock them. For each one, type the folder into the Imaging tab's **Image folder** box and leave the box; while the folder reads open, the Imaging tab offers **Lock this folder** - press it. That includes the old library inside TronForged's program folder (`<install>\TronForged.images`): it is never moved, and it is locked only when you lock it this way. Nothing is moved or deleted.
- **Lock or move old forensic collections.** Collections made before this release stay where they were, readable by every account on that PC, until you lock them from the **Forensics** tab (it names them; press **Lock that folder**) or move them to locked storage and delete the originals yourself. A collection on a USB stick or another drive formatted FAT or exFAT cannot be locked at all - anyone holding the stick can read it - so move it to an NTFS drive or other locked storage.
- **Look at the Status page's new lines** (see **The shop server**).

### Forensics

- **A collection goes into a new folder that only the PC's administrators can open.** The default is the first removable drive, else the first fixed drive that is not the system drive. With none, you choose; a folder on the system drive needs your confirmation, and the report records it. On a drive that cannot restrict access, such as most USB sticks, or on a network share, the console says so before collecting, and anyone holding the drive or reaching the share can read the collection.
- **Before collecting, the consent says who will be able to read the collection.**
- **After collecting, the console sends the fingerprints of the collection's two manifests and its report to your shop server**, which signs a record that it received them from that PC at that time. Only that signed record is attached to the ticket you chose, as a file the customer cannot see - never the evidence or the report. The record does not show how the evidence was collected. With a shop server older than this release, the record says it is not signed, and says the shop server needs updating.
- **The report names the PowerShell engine that ran the collection** and says which of its files are written in UTF-16 rather than UTF-8. On a PC with no PowerShell 7 installed for the whole PC, 13 of the network and system listings are UTF-16.
- **A collection opens inside the console.** TronForged never deletes one by itself: you can keep it locked, or copy it out with every copied file checked, and only after a checked copy delete the original - by typing your confirmation.

### Disk images

- **New image folders are locked to the PC's administrators** on a local drive that allows it. On a network share, or a FAT or exFAT drive, the console warns and changes nothing there.
- **The default place for new images moves off the Program Files folder**, to `TronForged\TronForged.images` on the first fixed drive that is not the system drive - never a drive connected by USB. Every image folder you already use stays listed and readable, the one in the program folder included, until you lock it (see **After you update**).
- **A capture never writes its image onto the drive it is reading.** Capturing an external drive refuses an image folder on that same drive. Capturing this PC into a folder on its own Windows drive leaves every listed image library out of the new image, so an image never carries copies of your other images. A capture that includes extra data volumes refuses an image folder on one of those volumes.
- **Images older than 90 days are flagged for review** in the image lists. Nothing deletes them automatically.
- **Image folders open inside the console.** In the image list, the right-click item is now called **Open folder**. Only an image folder that is locked opens in the console's viewer, and any page there opens as an internet page, with the restrictions a page from the internet gets - never with the trust of a file on the PC. A folder that is not locked opens in File Explorer as before.
- **Booting, restoring or cloning a marked image needs the backup permission to record your confirmation.** A technician without it is told so before typing anything.
- **An image a customer's login uploaded, or one whose uploader the server cannot tell**, is marked in the image lists, and booting, restoring or cloning it asks for your confirmation, which is recorded. The Server Console's **Backups** list shows the same mark. This applies to images downloaded with this release onward; an image downloaded earlier is treated as the shop's own. When the shop server was too old to say who uploaded an image, the image is shown as *Uploader unknown*, and the console asks the server again when you next boot, restore or clone it.
- **A disk-image file whose description does not follow the expected format is refused**, naming the field. Boot in VM keeps its working files in a folder the console lists.
- **Uninstalling TronForged keeps your disk images** and anything else you stored in its program folder that TronForged did not put there. It removes only what it installed, and the uninstall prompt says what is kept and where.

### Downloaded tools

- **Every tool TronForged downloads now has a recorded fingerprint and, where the vendor signs it, the vendor's certificate name.** Before keeping a download, and again before each launch, the console and the repair engine run a file only if its fingerprint matches, or if it is validly signed by that exact vendor and Windows confirms the certificate has not been revoked. Anything else is refused, the last checked copy is kept, and the vendor's page is offered. If a copy already on the PC is refused, the console also offers **Download a fresh copy**, which is checked before it replaces anything. A new fingerprint accepted on the vendor's signature is reported to your shop server.
- **Offline, a tool runs only if its fingerprint matches.** Tools whose files change between releases - MSERT, Trellix Stinger, the Emsisoft Emergency Kit, AdwCleaner and the Malwarebytes download - are accepted on their vendor's signature, which needs a connection to confirm. So offline, MSERT, Stinger and AdwCleaner run only if the copy on the PC is the exact one this release measured; otherwise they need a connection to run.
- **The Emsisoft Emergency Kit's scanner program is checked before each run**; the other files the kit unpacks are not yet checked, and will be in a later release.
- **DDU is checked when its self-extractor starts**; the program it extracts is the one you start by hand from the folder it asked for, and that one is not checked.
- **TDSSKiller is removed** (Kaspersky has retired it). **KVRT, GPU-Z, Complete Internet Repair, Dr.Web CureIt! and LicenseCrawler are shown as their vendor's page** instead of being downloaded: TronForged neither downloads nor starts them. The repair engine no longer downloads KVRT only to set it aside; the run's report says KVRT is shown as its vendor's page and was not run.
- **What winget and the PowerShell Gallery install** during the Patch stage is checked by those services themselves, not by the fingerprints above.
- **A tool your shop adds runs only after a technician records its fingerprint** with **Trust this file**, which your shop server records.
- **Downloads follow a redirect only to an https address**, and the ISO tab refuses an http link.

### The shop server

- **The server's own folder is locked** to Windows itself and the server PC's administrators. The server service reads and runs from it and writes only its own files. A fresh install refuses to finish when the lock does not read back, and an update that cannot lock it, or cannot give the service the access it needs, says FAILED and keeps running. Installing the server with the command line over a server that is already installed now refuses; use the Server Console's **Set up server > Update server** instead.
- **The server keeps its own log**, one file a day in its `logs` folder, and deletes each day's file after 90 days. Those day files are the only files the log deletes. The server's older housekeeping is unchanged: it keeps its newest seven daily database copies and deletes older ones, and it starts its crash log afresh once that passes 512 KB.
- **The Status page says** when one of the server's folders is open to other accounts, where the log is, and when a daily database copy was skipped. A copy is skipped only while its folder is truly open to another account; a folder that is merely owned by another account is shown in amber, and the copy is still made. The fix for both is **Set up server > Update server**. The folder check is capped - it lists the first findings and counts the rest - and does not walk every file of your backup store, so the Status page stays quick on a large one.
- **Old database copies.** Shop servers that ran the embedded database before v0.375.0 may have left daily copies of the database in your backup location. The server looks for them at each start, and the Status page names them, says that the card-number removal does not reach them, and deletes them only when you type the confirmation. That delete does not reach a NAS's recycle bin or snapshots, or a copy in a backup location you used earlier - remove those yourself.
- **Opening the server to the internet, a reinstall that wipes data, a forced uninstall and an administrator password reset** are each recorded before they happen; if the record cannot be written, they do not go ahead.
- **The server loads Windows' own system files only from Windows' system folder**, and a connection that arrives through the web transport is never treated as coming from the server PC itself.

### Scripts and PowerShell

- **The scripts TronForged writes and runs as administrator or as the system** - repairs, fixes, disk partitioning, Boot in VM - are written into a protected folder inside TronForged's data folder, and carry no values from disk images or other files in their text.
- **An administrator run never uses a per-user Microsoft Store copy of PowerShell 7.** It uses a PowerShell 7 installed for the whole PC, or else Windows PowerShell 5.1.

### Mixing versions

- **A console on this release with a shop server that is older** cannot record a disk-image confirmation, a shop tool's fingerprint or a folder lock until the server updates: the confirmation and the fingerprint are refused, and a folder lock still happens and says it was not recorded. Such a server also cannot sign a forensic record, so the record says it is not signed, and it cannot say who uploaded an image, so a downloaded image is shown as *Uploader unknown* until it can.

### The licence

The licence (`EULA.md`) changes in sections 5.2 (how downloaded tools are checked, and what that does not cover - corrected so that it speaks of the tools TronForged downloads: a tool shown only as its vendor's page is never downloaded, and what winget and the PowerShell Gallery install is left to their own checks), 5.3 (what is checked when PowerShell 7 and the .NET runtime are installed - a correction: the runtime's installer is checked by its Microsoft signature, not by a checksum), 11.2 (where forensic evidence is written, and the signed record), 12.1 and 12.5 (the shop server's 90-day operational log; 12.5 is corrected to name everything the server deletes on its own - that log's day files, daily database copies past the newest seven, and diagnostics past the periods in 12.2 - and that its crash log starts afresh past 512 KB), 13.1 and 13.3 (image folders locked, images flagged after 90 days, and image folders kept when TronForged is uninstalled), 14.2 (what uninstalling removes), and Schedule A (TDSSKiller removed). Using this release means accepting the licence as it ships with it.

### Not yet tested on hardware

As before, some of this has been tested only by the automated checks, not yet on real shop hardware: the locks read back as another user would see them, the server's folder lock on a live shop server, the old PostgreSQL folders' lock with the database running, and a capture of a PC's Windows drive into a library on that same drive. Some of the automated checks need administrator rights and have not yet been run with them. We will say in a later release when that bench run is done.
