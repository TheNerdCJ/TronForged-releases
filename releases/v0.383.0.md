## v0.383.0 - PowerShell 7 installs itself

TronForged uses PowerShell to repair machines. Windows ships with PowerShell 5.1, which every
PC has and which the product will always fall back to - but PowerShell 7 is faster and more
capable, and until now somebody had to install it by hand.

- **TronForged now installs PowerShell 7 itself**, quietly in the background, for the whole
  machine rather than for one signed-in user. That matters: a per-user copy is invisible to
  scheduled maintenance and to the before-login remote agent, so those would have kept using
  the older engine.
- **Nothing is required.** If the install cannot happen - no internet, a blocked download, a
  failed signature check - repairs carry on using the PowerShell that Windows already has, and
  the reason is written to `logs\runtime-ensure.log`. It re-tries at most once a day.
- **It is verified before anything is installed.** The download is checked against the checksum
  Microsoft publishes with the release, and **every program file inside it** must carry a valid
  Authenticode signature naming Microsoft - not just the launcher - or the whole thing is
  discarded.

**A new Prerequisites area** in Settings shows what is installed and lets a technician install,
update or remove PowerShell 7 by hand if the automatic path keeps failing. Remove only ever
removes a copy TronForged installed; one installed by hand or by Microsoft's own installer is
left alone. The Server Console has the same section for the server box, and it refuses to run
when you are administering that server remotely - otherwise it would install PowerShell on your
own laptop. A customer's console shows the status and no controls.

The .NET 10 runtime, which has installed itself since v0.339, is now handled by the same area.

Assets: `TronForged-0.383.0.exe` + `.sha256`, `TronForged.Server-0.383.0.exe` + `.sha256`.
