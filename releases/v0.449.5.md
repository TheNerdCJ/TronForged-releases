# v0.449.5 - v0.449.5: DYMO customer labels, and a wider live log

This release follows v0.449.4. It brings customer labels for DYMO label printers - the LabelWriter 450, 450 Twin Turbo and 550 - so a device and everything that came in with it always find their way back to their owner, and a roomier live log on the Automated service page. The shop server's program changes too, so update the shop server first. The licence changes; the changes are listed at the end.

## Customer labels (DYMO)

- **Labels for the device and everything that came in with it.** When you book a job in, the console can print a label for the device and one for each item brought in (charger, bag, cables and so on). A Service call booked with no device prints no device label.
- **What a label shows.** The customer's name and phone number - nothing else about them - the ticket number (and on an item's label, which item it is), your shop's own name and phone number, and a barcode. Your shop's details come from the Branding page on the Server Console; until they are set there, labels print without them and the console says where to set them.
- **The barcode holds only an internal reference.** It is one code per customer, made by your shop server the first time that customer's label prints. It never contains the customer's name, phone number or customer number.
- **Scan a label to open the customer.** Plug in a USB barcode scanner and scan a label into the new **Scan a label...** box on the Service desk (or into the search box). Press **Ctrl+Shift+L** from anywhere in the console to jump there. The customer opens with their open jobs. Only your shop's signed-in staff who work tickets can open a scanned label; a label from another shop, or one no customer has, simply says "No customer at this shop has that label."
- **Printing at book-in, or by hand.** Labels print by themselves after **Book in** (you can switch this off), and the booked-in page says what printed. If the printer has a problem the booking is still saved, the page says what went wrong, and **Print labels** prints them again. On any ticket, *Brought in with it* now has **Print labels**, **Device label** and a button for each item's label.
- **Print a customer label from the customer's profile, at any time.** On the Service desk's Customers view, every customer (business or household) now has **Print label**: their own label - name, phone, your shop's details and the barcode - with no ticket needed, 1 to 50 copies. If the customer has open jobs, you can add one job's item labels to the same print.
- **A label always carries the customer's name.** If the console cannot read the customer's name from the shop server, it prints nothing and says so, rather than printing a label without a name.
- **Settings, Customer labels.** Each counter PC chooses its own label printer and label size, can switch printing at book-in on or off, and can print a test label. On a LabelWriter 450 Twin Turbo, choose which roll (left, right or automatic) - the choice appears only for a printer with more than one roll and is remembered for each printer. Supported sizes: DYMO 99015 (54 x 70 mm, upright - the default), 30252 (28 x 89 mm), 99012 (36 x 89 mm), 30336 (25 x 54 mm) and 30334 (32 x 57 mm). Long names shrink to fit and are shortened with "..." when they must be; the barcode is never cut or squeezed.
- **Works with the printer's own Windows driver.** The DYMO LabelWriter 450, 450 Twin Turbo and 550 install as ordinary Windows printers; no DYMO Label Software or DYMO Connect is needed. The console asks the driver for the right label stock and roll. Any label printer with a Windows driver may also work.
- **The LabelWriter 550 prints only on genuine DYMO labels.** On any other roll the printer refuses the job, and the console says so: "The printer did not print the labels ... Check that the roll is genuine DYMO labels". The console says "Printed" only when it has seen the printer print the labels; if it cannot see that - or the job simply disappears from the Windows print queue - it says the labels were sent and what to check.

## The Automated service page

- **The live log now takes the wide left column, at full height**, so you can read more of what the run is doing. The stages to tick sit on the right, under *This job*. Nothing else on the page changes.

## Before you update

- **Update the shop server first** (Set up server > Update server, on the server PC), then the consoles. On its first start the shop server adds its new table for label codes; nothing already there is changed.
- **With an older shop server the labels still print, but without a barcode**, and scanning a label says the server needs updating.

## After you update

- **On each counter PC that prints labels, open Settings > Customer labels**: choose the label printer and the label size, the roll on a Twin Turbo, and whether labels print at book-in, then print a test label. Each PC chooses its own. On a PC with no label printer chosen, book-in prints no labels and says to choose one there, and **Print labels** asks which printer.
- **Set your shop's name and phone number on the Server Console's Branding page**, if you have not already, so they appear on every label.
- **On a LabelWriter 550, load genuine DYMO labels.**

## The licence

The licence changes in these places:

- **Sections 16.6** (for the shop) **and 19.4** (for the customer) now describe the labels: that they are printed at book-in or at any time from the customer's record or a ticket, for the customer, the device and each item brought in; what they show; and that scanning one opens the customer's record only for your signed-in staff with permission to see it.

## Not yet tested on hardware

Customer labels have not yet been tested on a real DYMO printer or a real barcode scanner. The label sizes, margins and barcode have been checked in software, including reading the barcode back from a rendered image. If a label prints cut off or turned the wrong way on your printer, please tell us which printer model and label size you use. The Automated service page's new layout has not yet been checked at different display scalings on a small laptop screen.
