## v0.377.0 - the installer fetches the latest release before it installs anything

**The file you run now checks for a newer TronForged first.** Before the console chooser opens, an uninstalled `TronForged.exe` asks the release feed whether a newer `TronForged-<version>.exe` has been published. If one has, it downloads it into a folder locked to administrators, verifies it against the release's published `.sha256` (and, when the copy you ran is code-signed, refuses an unsigned download), and runs *that* copy - which shows the same chooser and installs itself. A stale download can no longer install a stale console.

- Offline, or refused: the window says why and offers to install the version in hand. The check can only make an install current, never prevent one.
- `TronForged.exe --no-update-check` skips it (an offline bench). The fetched successor is launched with the same argument, so the check is one hop, never a loop.
- An **installed** console is unchanged: it updates from the shop server only.

**Read this before relying on it: the release feed is private.** The first live run of this feature, from a machine holding no GitHub token, was answered 404 - so on every customer and technician PC the front door currently reports *the release feed is private and this PC holds no access to it* and installs the version in hand. Only the server box (whose `server.json` carries the token) can read the feed today; with a token the whole chain was exercised live on both runtimes. For the check to work in the field the shop owner must either make the release repository public or publish the four release assets to a public releases-only repository and point `updateFeedRepo` at it. `README.md` and `docs/SERVER_SETUP.md` describe this.

Under the hood:
- One GitHub request shape for the whole product (`GitHubHttp`): User-Agent, JSON Accept for the feed, octet-stream + Authorization for assets; a streaming download that watches for a stall, observes an abandoned read, and never leaves a partial file. The Server Console's server-program update rides it.
- One answer to "which repository" (`ServerConsoleWindow.ResolveFeed`) and one default (`GitHubFeed.DefaultRepo`) where three literals used to sit.
- `LauncherUpdateProbe` (35 checks, both runtimes), pins (a)-(j) calibrated by 26 mutants, and xaml-check constructs the new window off the built carrier.

Assets: `TronForged-0.377.0.exe` + `.sha256`, `TronForged.Server-0.377.0.exe` + `.sha256`.
