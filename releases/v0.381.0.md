## v0.381.0 - a technician's visit leaves nothing behind

When a technician signed in on a customer's PC, three things stayed on that computer after they left. They no longer do.

- **The shop's fleet list.** While a technician was signed in, the console saved the shop's list of reachable machines onto the customer's own disk - each entry carrying another customer's machine name, **their business name**, and **that machine's unattended remote-access secret**. It was encrypted to the Windows account it was written under, which on a customer's PC is the customer's own account. That list is now held in memory only while the technician is present, and never written to a customer's machine. Their fleet tiles and Reconnect work exactly as before.
- **Unsent Service Desk notes.** Draft replies and internal notes typed about other customers' jobs were left in plain text.
- **The technician's cached credential** was already removed on sign-out; now it is removed by the same sweep, which also runs when the program is force-quit (it did not before).

Ending a technician session - by signing out, by the two-hour limit, or by quitting - now clears all three from the customer's machine, closes any shop windows that session opened, and says so if anything could not be removed rather than reporting a clean machine.

*Found by an isolation audit of the customer console. The audit's headline is worth stating: the ordinary customer console did not reach another customer's data anywhere it was tested - every other customer's ticket, invoice and backup answered "not found". This release fixes what a visit left on the machine itself.*
