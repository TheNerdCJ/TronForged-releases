# TronForged v0.494.0

The fleet's Windows Server window is faster and easier: no Remote in first, it keeps your place, it acts on several
rows at once, it finds things on a large domain, and it manages services.

## No Remote in first

- **Where.** Fleet and remote: press **Windows Server** on a customer's server row. You no longer press Remote in first.
- **What it opens.** The window opens its own management connection to that server: the same encrypted pairing
  through your shop server as Remote in, using the unattended access enabled on that server, but no screen. Your
  shop server finds that access itself, so nothing needs to be saved on your console first. It
  carries only the window's lists and actions. It cannot see or control the server's screen and it never takes
  control from anyone. A technician who is controlling the screen does not make it read-only, and when another
  technician is on the screen your window can still act with your own permission, audited under your name.
- **Who may open it.** Technicians holding **winsrv**, or **winsrv.read** for the lists only. The **remote** permission
  is neither needed nor enough, and an account linked to a customer never may. The two-factor code is asked exactly as
  for Remote in (once per server every 10 minutes); the window asks for it itself. It opens only to a Windows Server
  your shop manages, never to a workstation or to the shop's own server box, and the shop server records every refusal.
- **What the server shows.** Its banner says **Windows Server management connected** and a notice names the
  technician. The shop server's audit log records each connection as *Windows Server management connected* with the
  technician's name. The server's "while you were away" notice counts these connections apart from remote support
  sessions and says they did not see the screen.
- **When it ends.** When you have closed the window and every wizard you opened from it (domain controller, cluster,
  move a VM), and after 20 minutes with nothing sent - never while an action is still running; the next action
  connects again.
- **When it cannot connect** the window says why in one sentence and offers Remote in - for example *This server's
  TronForged is older than 0.494.0 - use Remote in.*, *The shop server is older than 0.494.0 - update it, or use
  Remote in.*, *This server has no unattended access enabled. Turn it on at that server, or use Remote in.* or *This
  server refused the management connection:* with the server's own reason. It never switches to anything else on its
  own. After a cancelled two-factor code it says to press Refresh to enter it.
- If you already have a remote session open to that server and you control it, the window uses it, as before. While
  you only watch another technician's session, the window uses its own connection.

## Quicker every day

- **One window per server.** Pressing Windows Server again brings the open window to the front.
- **The list keeps your place.** After a change the list keeps your search, as many rows as you had loaded, and the
  row you chose.
- **Several rows at once.** Select rows with Ctrl or Shift. With two or more selected you get only the safe actions:
  unlock, enable, disable, add to a group and remove from a group for Active Directory users, enable and disable for
  local users, and start, shut down and save for virtual machines. Each row is its own authorised and audited request,
  one after another, with one result line per row and a Stop button. Up to 50 rows at once. If the connection to the
  server cannot open, the batch stops at once and says why. Deletes, password resets, offboard, moves and cluster
  actions stay one row at a time.
- **Clear results.** One row's change says what was done to whom, for example *ann - unlocked.* Actions that cannot
  be undone are greyed out, with the reason, for an account without winsrv.admin.
- **Search first on a large list.** Above 1,000 items the page shows the first page, says for example *4,812 users -
  search to find one.* and puts the cursor in Search.
- **Locked out and Disabled.** Two buttons above the Active Directory users find just those accounts on the server,
  beyond the loaded page. Local users have Disabled only.
- **Servers in the fleet.** A **Servers** button on Fleet and remote shows only your customers' Windows Servers (also
  on the Unattended Fleet tiles), each with its roles: Domain controller, Hyper-V, Cluster member.

## Services

- A new **Services** section on every server whose helper is 0.494.0 or later: each service with its status and start
  type, search, and **Start**, **Stop**, **Restart** and **Set start type** (Automatic, Manual, Disabled).
- Stopping, restarting or disabling a service that others depend on names them and asks you to confirm.
- The core role services - NTDS, Kdc, DFSR, IsmServ and ADWS (Active Directory), DNS, Netlogon, vmms (Hyper-V) and
  ClusSvc (the cluster service) - need **winsrv.admin** and the service's name typed to stop, restart or disable. A
  change that would reach a running core service through its dependants is refused with a sentence naming it.
- A restart whose dependants did not all start again names them.
- TronForged's own services are never listed and are refused, by your shop server and by the server's helper.

## Versions

- The management connection needs your shop server, your console and the customer's server on 0.494.0. Update the
  shop server first. With an older customer server, use Remote in as before.
- Services need the customer's server's helper at 0.494.0.

## Known limits

- Not yet tested on real hardware: the management connection and the Services section. A Windows Server 2022 and 2025
  bench is planned. The several-rows pane, the Locked out / Disabled buttons and the role chips have not yet been seen
  in a running window.

- A connection that died quietly while idle is noticed after about 95 seconds; an action sent in that gap reads as
  unknown, and the next one connects again.
- A service whose name contains a space is listed but offers no buttons.
- An Active Directory account that is both locked and disabled reads *Locked*, also under Disabled.
- The Customer, Site and Group counts on Fleet and remote do not follow the Servers button.
- A server on an older TronForged that reports only that it is a server is listed under Servers without role chips.
