# v0.449.0 - v0.449.0: customer logins and billing, AI kept off regulated customers, run notifications from the shop server, and checked outbound connections

This release follows v0.448.1, and these notes cover everything that changed since then. If your shop server has not taken v0.448.1 yet, read the v0.448.1 release notes too: everything in them applies to this update as well.

This is a security release. In short:

- **A customer login that is not linked to a customer record can no longer touch invoices, payments or accounting.** An older login that the shop server still matches to a customer by its email address keeps seeing that customer's own tickets, but every billing action is refused, and the Server Console offers a **Link** button for it.
- **AI is kept off customers in healthcare, legal, financial and government work** until an administrator records that the shop has the right agreement with Anthropic, and the ticket AI features now run only with an API key - never with a Claude subscription sign-in.
- **Run notifications go out from your shop server's mailbox.** No PC keeps a mail password any more; each PC's old copy is securely deleted when this release first starts there.
- **A business's PCs each see only their own tickets** in *Messages from your shop*, and staff can see which PC a customer answered from.
- **The customer form and address lookup are fixed** - the Known issues earlier notes carried for them are gone (see **The customer form and address lookup**).
- **Every HTTPS connection uses Windows' own security settings and checks whether a certificate was revoked**, and the shop server will not send addresses or mail to a machine on your own network unless you switch that on.

This release updates the consoles and the shop server's program, and it adds to the structure of your shop's database (see **Going back to an older release**). The licence changes too - see **The licence** below.

### Before you let your shop server take this update
- **If your shop server sends mail through a mail server on your own network** (a relay, Exchange or NAS in the shop), mail - invoices and run notifications - stops at the update until you allow it (see **After you update**). A mail relay running on the shop server PC itself can no longer be used: point the server at your provider's or the in-shop mail server's own address instead.

- **Plan to update the shop server first, by hand**, before your other PCs take this release: on the server PC, **Server Console > Settings > Updates for this PC > Update everything on this PC**. Several of the changes below need both sides on this release - see **Mixing versions**.
- **Find and link the customer logins the server matches by email.** On the server PC, run `server\Find-CustomerBoundStaff.ps1` from this release (from an administrator window; it opens the database read-only and changes nothing). For each login it lists with a *Link candidate*, open **Server Console > Users & groups** after the update and press **Link** on that login's row. If it says *Link candidate: none* (several customers share that address), open the login with **Edit** and choose its customer instead. From this release such a login cannot pay or view invoices until it is linked.

### After you update

- **Set who hears when a run finishes.** On **Server Console > Email**, under **Run notifications**, type the addresses that should receive a short summary of each finished repair run (up to ten, separated by commas), and save. A PC's old list is not carried over, and nothing is sent until this list is set. The shop's mailbox on that page is the one invoices already use.
- **Tag your regulated customers.** The Server Console lists, once, the customers that have no sector yet. Open each customer whose work is healthcare, legal, financial or government and set its sector in the customer form's **AI and regulated data** section. AI is off for those customers by default. Until a customer is tagged, nothing keeps AI off its tickets - so if you serve healthcare clients, keep the ticket AI features switched off until this is done.
- **If your mail server is on your own network** (for example a mail server or NAS in the shop rather than a provider on the internet), the shop server now refuses to send to it until you allow it: on the server PC, add `"allowInternalServices": "on"` to the server's `server.json` (from an editor run as administrator) and restart the TronForged server service. There is no switch for it in the Server Console. The server's setup guide says what counts as your own network.
- **Leave the run webhook unset.** The shop server can also post each run summary, signed, to a web address of yours, but no page of this release sets that address or shows its signing secret, so a receiver cannot check the signature yet. A later release adds it.
- **Nothing needs to be redeployed.** Unlike v0.448.1, this release asks you to redeploy nothing - not the Claude CLI and not the helper.
- **Expect a PC's tray to show only its own tickets.** A ticket opened at the counter reaches a customer's PC only when staff attach it there: open the ticket and use **Attach to this customer's PC**.

### Customer logins and billing

- **One rule decides whether a login belongs to a customer.** A login linked to a customer record is that customer, as before. An older login that is not linked, but whose email address is a customer's contact email, is still treated as that customer for its own tickets - and from this release it is refused every invoice, payment and accounting action. So is a login whose email address belongs to two customers.
- **Link it in one click.** On **Server Console > Users & groups**, such a login's row offers **Link**. It is an administrator's action, and it is recorded in the audit log.
- **Changing a customer's contact email can move a login to another customer**, so from this release that change needs an administrator, and every such move is recorded with the old and the new email.
- **The shop server's log names, at each start, any account in the Customers group that also holds staff permissions.** It changes nothing.

### AI and regulated customers

- **Each customer now has a sector.** For customers in healthcare, legal, financial or government work, AI is off by default. An administrator can turn it on for one of them only while the shop server uses an Anthropic API key, and only by recording that the shop has a business associate agreement or a zero-data-retention agreement with Anthropic covering that customer's data. The record names who made it and when, and changing how the server reaches the AI provider cancels it.
- **The ticket features - Brief a ticket, the reply and resolution drafts and the customer summary - now run only with an API key**, for every customer. With the Claude subscription option chosen they are refused, and the Server Console asks before you switch to that option.
- **The Service Desk shows where AI is off and why** (*AI off - regulated customer*, *AI off for this customer* or *AI: API only*) and offers no AI button there. The fleet health and server sizing summaries carry no customer messages and are not affected.
- **With the Claude subscription option, each request now runs Claude's program in a throwaway folder** with its telemetry and error reporting switched off; the folder is deleted afterwards.
- **What is sent to the AI provider masks more.** Network addresses and computer names are now masked in a ticket brief, as passwords, keys and card numbers already were.

### Tickets

- **A business's PCs each see only their own tickets.** *Messages from your shop* on a PC shows the tickets opened from that PC and those the shop attached to it - not a colleague's or the owner's. Staff attach a counter ticket with **Attach to this customer's PC** on the ticket.
- **Staff see which PC a customer answered from** on each message.
- **A reinstalled and re-enrolled PC keeps its open tickets.** They follow it to its new enrolment; a resolved or closed ticket stays with the machine it was worked on. The move is recorded in the audit log.
- **Every message has a length limit, and a message over it is refused with a sentence that says which field and what the limit is** - a subject 200 characters, a PC's label 64, a customer's message 4,000, a staff message 20,000. Before this release a long customer reply was cut short without a word.
- **A customer's login, and each PC, may open or answer 20 tickets an hour** together (staff 600).

### Email and run notifications

- **Run notifications come from the shop server.** When a repair run finishes, the PC hands your shop server a short summary - technician, ticket number, computer, counts and outcome; never the report or any file - and the server mails it from the shop's mailbox to the list on the **Email** page. An unattended run, and one that resumed by itself after a restart, is notified too. A summary the PC could not hand over waits on that PC and is dropped after seven days.
- **No PC keeps a mail password.** The first time this release starts on a PC, it securely deletes that PC's copy of the shop's mail password. A build no longer carries mail settings at all.
- **The recovery key is never emailed**, and the old *Use recovery key* sign-in reset is gone. An old local account vault opens only to be imported into your shop server.
- **Changing the mail server, its port or its sign-in name now needs the mailbox password typed again**, so a saved password is never sent to a new server. A send that cannot reach the mail server says only *Couldn't reach the mail server*; the server's log has the detail.

### The customer form and address lookup

- **The Service Desk card edits the customer as it is now**, and redraws after a save - a second edit from the same card no longer puts back the old name or drops a mailing or shipping address.
- **The form asks the shop server what it can keep** before it offers a field, and says so when it cannot tell.
- **Switching between Household and Business keeps the name**, a cleared contact person stays cleared, unticking Packages before Mail keeps the typed shipping address, a refused save scrolls its reason into view, and Cancel after Register or Save can no longer half-close the form.
- **"Residential" is now called "Household"** everywhere it is shown.
- **The ZIP note appears only for a United States address** (or a blank country in a United States shop).
- **Address lookup no longer holds up the console.** A console may have two lookups waiting and the shop server eight; one more is answered *Address lookup is busy* at once. Tab and Escape stay in the form, a pick fills only the parts the suggestion has, and the **Address lookup...** button is always on screen.
- **A self-hosted Photon server of any version works.**
- **An address check is kept only for the address it checked** (the apartment line is not part of it).
- **A billing address changed from a console older than v0.449.0, or by a RepairShopr re-import, now clears its country** (it becomes the shop's own) and its address check, and the audit log records it.

### Connections and downloads

- **Every HTTPS connection uses Windows' own TLS settings and checks revocation**: a site whose certificate has been revoked is refused; when the revocation server cannot be reached the connection goes ahead.
- **A download that starts with `http://` is refused** before anything is fetched, and no connection follows a redirect it was not meant to.
- **The shop server sends addresses, run notifications and mail only to public addresses over HTTPS** (mail over its own encrypted connection), never to the server itself, and to a machine on your own network only when you allow it (see **After you update**).
- **The Patch stage takes winget's installer and HP's update tool only from folders a standard user cannot change.**

### Windows updates

- **"Restart now" waits while a job is running.** If a repair run, a disk image, a Data Recovery job, a remote session or another listed job is under way when updates finish, the PC waits until it is idle, as *restart when idle* does, and says so in the tray.

### Disk images

- **A library inside a folder other users can change says so** on its card: a locked library there could be renamed away and another folder put in its place. Nothing is refused or changed; move the library into a folder only administrators can change.
- **A capture keeps Windows' own list of files it does not compress**, which the exclusion list from v0.448.1 had dropped.
- **An image asked about while the shop server cannot be reached** now says the server could not be reached, instead of telling you to update it.

### Diagnostics

- **The diagnostics each PC sends your shop server now also mask IP addresses, the host names in addresses and paths, `.local` and `.lan` names and the PC's own name**, and the shop server masks them again as they arrive.

### Mixing versions

- **Update the shop server first.** A console on this release with an older shop server cannot send a run notification (the older server does not know the request, so none is sent), cannot show which PC answered or attach a ticket to a PC, and cannot set a customer's sector.
- **A console older than this release with a shop server on this release**: its billing edits clear the customer's country (to the shop's own), it keeps sending its own run notifications with its own mail settings until it updates, and it shows a business's PCs only their own tickets because the server decides that.
- **A PC older than this release keeps its own copy of the mail password** until it updates; the first start of this release there deletes it.

### Going back to an older release

This release adds to your shop's database (a customer's sector and AI setting, who enrolled each PC, and which PC a message came from). A shop server older than this release refuses to open the database afterwards. To go back, restore the database copy taken before the update together with the older program; anything entered since is lost with it, and an older server has no rule that keeps AI off a regulated customer's tickets - switch the ticket AI features off first. The server's setup guide says how.

### The licence

The licence (`EULA.md`) changes in sections 10.2 (an uninstall leaves the Ctrl+Alt+Delete setting on until a later release), 10.3 (the shop server relays a remote session and holds the unattended secret, so it could join one), 11.4 (a console sends no email), 12.2 and 15.2 (network addresses and host names are masked), a new 15.4 (AI and regulated customers), 16.3 (email goes out from the shop server's mailbox, and what a run notice carries), 16.4 (when the shop server contacts GitHub; HTTPS only and no private addresses unless the shop allows it; Claude's program in a throwaway folder), 16.5 and Schedule A (what each address lookup carries, and that a check can go to another geocoder the shop names), and 21.5 (the shop server derives and holds the team chat key, so it can read team chat). Using this release means accepting the licence as it ships with it.

### Not yet tested on hardware

As before, some of this has been tested only by the automated checks, not yet on real shop hardware: run notifications from an unattended and a resumed run, the revocation check on a live network, address lookup against the real services, a mail server on the shop's own network, "restart now" waiting for an idle PC, the image library's folder warning, and the AI setting for a regulated customer end to end. Some of the automated checks need administrator rights and have not yet been run with them. Release updates are not yet signed with your shop's own key; that arrives in a later release. We will say in a later release when the bench run is done.
