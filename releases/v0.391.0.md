## v0.391.0 - forensic collections stop losing non-English names

**If you have run a forensic collection on a machine where anything was named in a language
other than English, that name was damaged in the saved evidence.** This release fixes it.

### What was wrong

The collector saves most of its findings as CSV files - the process list, the USB history, the
logon timeline, the file hashes, and about thirty more. Those files were being written in a
format that can only represent plain English characters. Anything else was replaced with a
question mark, on disk, permanently.

A file named in Russian came out as `????????.exe`. A user folder with an accented name
came out with the accent replaced by a question mark. A program named in Chinese or Japanese
came out as question marks with a `.exe` on the end. The rest of the row - the path, the
timestamps, the hash - was intact, but the name itself was gone from the evidence, and there
was no way to recover it from the saved file.

This affected 37 of the 38 CSV exports and all 3 of the text exports. One CSV was already
correct, which is why it was easy to miss.

### What changed

Every file the collector writes now names its format explicitly, from one setting rather than
forty. Names in any language are preserved exactly as they were on the machine, and the files
open correctly in Excel.

**This does not repair collections you have already taken.** The question marks in an existing
evidence folder are what was written to disk. If a past collection matters and it involved
non-English names, it is worth re-running on the same machine if that machine is still
available.

### Also in this release

- Forensic collection now runs on PowerShell 7 like the rest of TronForged. It was deliberately
  held back one release, because moving it before the fix above would have changed the format of
  saved evidence as a side effect. Both engines now produce identical files, so it no longer
  matters which one a machine has.
- The chain-of-custody section of the forensic report was checked against the new file format
  before the change shipped, not after.

Assets: `TronForged-0.391.0.exe` + `.sha256`, `TronForged.Server-0.391.0.exe` + `.sha256`.
