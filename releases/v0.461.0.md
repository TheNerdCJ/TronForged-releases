# v0.461.0 - TronForged 0.461.0 - tighter security on the technician's PC

## TronForged 0.461.0 - tighter security on the technician's PC

This release closes a set of local security gaps: places where TronForged left sensitive files readable by other
people on the same PC, or in a temporary folder anyone could reach. Nothing new needs to be switched on.

### Forensics: saved Wi-Fi passwords are no longer kept in plain text
- When a forensic collection includes saved Wi-Fi passwords, they are now sealed with your shop's key the moment
  they are collected, and the plain copy is shredded. The evidence fingerprints and custody record describe the
  sealed files.
- Sealing needs a console signed in to the shop server as a technician with the backup permission, or the shop's
  recovery key loaded. Without either, the collection is refused before anything is collected - sign in, or untick
  Wi-Fi passwords. If a profile cannot be sealed, the plain copy is shredded anyway and the report says the Wi-Fi
  passwords were not kept.
- When you keep a bundle, you can now choose **Copy encrypted to...** to copy it to another drive with every file
  sealed and checked. The Forensics tab has a new **Open Encrypted Copy...** button to open such a copy again.

### Fewer files in temporary folders
- The disk speed test, the battery report and the blue-screen summary now work in a private, locked folder that is
  deleted when they finish, instead of the shared temporary folder.
- A PC transfer package's list of contents is sealed and opened in memory, and never written to a temporary
  folder in the clear.
- Encrypted copies on an external drive no longer show each file's fingerprint in plain sight. Copies made by
  older versions still open.

### The program's own working files are locked
- When TronForged runs as an administrator or as a Windows service (the agent, the shop server, scheduled
  maintenance), it now unpacks its working files into a folder only administrators can change, inside its own
  data folder.
- Old copies of those working files left behind by earlier versions are cleaned up automatically when the console
  starts.

### Repairs and imaging
- The file-permissions reset repair (`resetFilePermissions`) no longer strips the protection from TronForged's own locked folders
  under the Users folder; it puts it back and checks it.
- A Windows system image made by TronForged on a local drive is now limited to administrators. On a network share
  or a FAT/exFAT drive it cannot be, and the report says so.
- If a disk clone stops and keeps its staging image on an external backup drive, that image is now encrypted. If
  encryption is not possible, the status line says the image is NOT encrypted and how to fix that.

### Other fixes
- A remote repair run now always records the technician the server signed in, not whatever name was typed in the
  Tech box. The ticket and customer you typed are kept.
- Setting up or updating the shop server repairs the permissions on its database, backups and audit folders without
  undoing their own locks.
- Saving offline sign-in details from two places at once can no longer lose one of them.

### What to do
- Nothing for most shops. Update the server and consoles as usual.
- If you use scheduled maintenance, open it once and press **Apply schedule** so the scheduled task picks up the
  new locked working folder.
- To keep saved Wi-Fi passwords in a forensic collection, sign in as a technician with the backup permission (the
  shop server provides the key that seals them).
- The Wi-Fi export is in plain text on the evidence drive for the moment between Windows writing it and the shred;
  on an SSD or USB flash drive pieces of it can stay recoverable until overwritten.
