# v0.390.0 - PowerShell 7 becomes the engine

## v0.390.0 - PowerShell 7 becomes the engine, and one-click fixes get safer

**PowerShell 7 is now what TronForged runs your repairs on.** It has been installing
PowerShell 7 on your machines since v0.383.0; from this release it actually uses it
everywhere, rather than only for the repair engine and imaging.

Nothing is required of you, and nothing breaks on a PC that does not have it. If PowerShell 7
is not installed - the install has not run yet, or it could not reach Microsoft to download it
- TronForged falls back to the Windows PowerShell that every Windows PC ships with, exactly as
before. You are not asked to install anything, and no fix stops working.

One visible improvement comes with it: a few of the diagnostic fixes used to print a red
PowerShell error above their results, on a machine where nothing was actually wrong. The
"Recent changes report" was the clearest case. Those now print cleanly.

### A security fix in the Windows Fixes tab

**What was wrong:** the Windows Fixes tab runs as administrator, and some fixes work by
running a small script. TronForged was naming the programs those scripts use by short name -
`powershell`, `net`, `reg` and so on - and letting Windows decide which file that meant. That
decision is made from the folder the fix happens to be running in, before anywhere else.

So a file with the right name, sitting in the wrong folder, could be run instead of the real
Windows program - with administrator rights. Worse, it happened quietly: the substituted file
also stopped the rest of that fix from running, so the fix looked like it had finished rather
than like it had been interfered with.

**What changed:** every script TronForged generates now runs from a fixed system location
rather than wherever it happens to be, and looks for Windows programs in the real Windows
folders first. The PowerShell engine is no longer named by short name at all - the exact
program is chosen up front. This covers all 370 commands in the fixes catalog, not only the
ones that use PowerShell.

We have no evidence of this being used against anyone. It was found by auditing our own code,
and it is fixed for every fix in the catalog rather than the handful that prompted the audit.

### Also in this release

- The report a fix gives you keeps quoting the machine's own words. Moving to PowerShell 7
  changed how Windows formats error text, which would have replaced the reason for a problem
  with a file path. It does not.
- The check that is supposed to catch this whole class of problem could not see the fixes
  catalog at all, and would still have missed it after the obvious correction. It now checks
  247 files and names the exact fix it objects to.
- Forensic collection deliberately stays on Windows PowerShell for now. Changing its engine
  would change the file format of collected evidence, and that is not something to change as a
  side effect of an unrelated release.
