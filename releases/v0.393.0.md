# v0.393.0 - The catalog tells you why a build is stuck

## v0.393.0 - the catalog now tells you why a build is stuck

The last release fixed servers that had stopped receiving new versions. This one answers the
other question that page could not: **why is a release sitting at "canaries only" and not
reaching the rest of the shop?**

### What was wrong

TronForged rolls a new version out in two steps - first to your canary machines, then to
everyone once a canary has confirmed it and 24 clean hours have passed. When it decides not to
take that second step, it records exactly why, and it records a different reason for each cause:

- no machine in your shop is in the canary ring, so nothing can confirm the build
- a canary exists but has not installed this build yet
- a machine reported a failed update, which holds the rollout on purpose

All three were written to the audit log, and nothing in the console ever read them. So the
Updates page showed a release marked CANARIES ONLY, month after month, with the explanation
sitting on a different page you had no reason to open.

### What changed

The catalog now reads those records and prints the reason directly under the release it belongs
to, in amber - the same colour the page uses for "waiting on something" rather than "broken".

If the reason is that nothing is in your canary ring, the fix is one click: **Settings ->
Console updates -> Which consoles get updates first (canaries)**, and set a machine - your bench
PC, or your own console - to Canary.

### Also

If a release is held because a machine reported a failed update, the line now names that
machine, so you know where to look rather than which build to blame.

Assets: `TronForged-0.393.0.exe` + `.sha256`, `TronForged.Server-0.393.0.exe` + `.sha256`.
