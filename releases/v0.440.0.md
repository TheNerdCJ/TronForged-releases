# v0.440.0 - Separate mailing and shipping addresses

A customer used to have one address for everything, so a customer who collects mail at a PO box had nowhere to put the street where parcels should go. The address on the customer form is still the billing address - the one printed on invoices and sent to QuickBooks - and you can now say where mail goes and where packages go when that is somewhere else. For nearly every customer nothing extra is typed. This release updates the consoles and the shop server. The first time the updated server starts, it adds to the shop's database, and after that an older server version cannot be put back without losing data - read **Before you update**.

### On the customer form

- **Two new ticks under Address:** **Mail goes to this address** and **Packages ship to this address**. Both are ticked for a new customer and for every customer already on file. Leave them ticked and nothing more is typed.
- **Untick one to give it its own address.** Unticking **Mail goes to this address** opens a **Mailing address** - for example a PO box for mail, while parcels still go to the street. Unticking **Packages ship to this address** opens a **Shipping address**.
- **Packages can follow the mailing address.** When both ticks are off, packages go to the mailing address, so it is typed only once. Choose **Ship to another address** instead to give packages an address of their own.
- **They follow, they are not copies.** Mail and packages that go to the billing address move with it when it changes later, and packages that follow the mailing address move with that. Nobody has to retype anything.
- A mailing or shipping address left empty counts as "same as the billing address", and its tick is back on the next time the form opens.
- **Outside the shop's country?** under each address opens a **Country** box for a two-letter code (for example CA or GB). Leave it blank for the shop's own country, which is what most customers need. Anything other than two letters is refused with a message before saving.

### Where you see it

- **Service Desk > Customers**, a customer's card: **Address** now shows the whole billing address - street, apartment or unit, city, state and ZIP, and the country code when one is set. It used to show only the street line. **Mail to** and **Ship to** appear under it only when they go somewhere other than the billing address.
- **Customers & fleet** (in the Server Console, or **Server administration** on a technician console): a selected customer's details now show the billing address, with **Mail to:** and **Ship to:** lines when those differ.
- **Printed invoices** still bill to the billing address, and add the two-letter country code on its own line when one is set. Mailing and shipping addresses are not printed on invoices.
- **Server Console > Accounting > QuickBooks Online - customer list (.csv)**: the Country column now carries the billing address's country code when one is set, and stays blank for the shop's own country. Mailing and shipping addresses are never sent to QuickBooks.

### Before you update

**This update cannot be undone just by installing an older server version.** Once the updated server has added to the database, an older server version will not start with it. Going back would mean restoring a copy of the database made before the update, and losing everything entered since - tickets, invoices, payments and customers. The Server Console cannot do that for you: its **Restore database...** always runs the installed server program, which adds the new storage to the copy again. If you want to keep that possibility open:

- **Make a copy before your server updates itself.** A shop server can update itself within a few hours of a release, whenever the shop is idle. On the server PC, open the Server Console and press **Settings > Database maintenance > Back up database...**, then update by hand (see **After you update**).
- **The daily copies.** The shop server also copies its database once a day, into `C:\ProgramData\TronForged\server\backups\db\` on the server PC on a standard install (named `tronforged-<date>.db`; the folder needs administrator rights). It keeps only the newest seven, so about a week after the update none from before it is left. If you want one, copy the newest one made before the update - go by the time the file was modified - somewhere safe.
- **Neither kind of copy is encrypted.** Each holds every customer, ticket and invoice and the credentials of every enrolled console, so keep it somewhere only you can reach.

### After you update

- **Update the shop server by hand if you can:** on the server PC, **Server Console > Settings > Updates for this PC > Update everything on this PC**. Then someone is watching when it adds to the database (see **Known issues**), and your consoles and server match sooner.
- Every customer already on file keeps one address for everything until somebody unticks a box.

**While the consoles and the shop server are on different versions:**

- Mailing and shipping addresses and the country need the shop server on v0.440.0. Until your server has updated, an updated console greys out the two ticks, with the reason, when you **edit** a customer - but not when you **register a new customer**, and never the country box. Leave both ticks on and the country blank until the server has updated: an older server does not keep them. If you do type a country, the console may say it "was shortened to 0 characters" - it was not kept at all.
- A console that has not updated yet keeps working with an updated server. It shows and prints the billing address as before, without the country, and does not show mailing or shipping addresses. Saving a customer from it leaves their mailing and shipping addresses and country exactly as they were.
- Nothing changes in the customer console.

### Known issues

- **If consoles cannot reach the shop server after it updates**, open the Server Console on the server PC and press **Settings > Updates for this PC > Update everything on this PC**. If the updated server is slow to come up - for example while antivirus scans it - the update puts the previous server program back and may say the shop is still online, but the previous program cannot open the updated database. This is uncommon.
- **After Edit contact details, the customer card still shows the old details**, including its old Mail to and Ship to lines. The save works, but the card in the Service Desk is not redrawn until you open the customer again from the list. Open it again before you edit it a second time: editing from the old card puts the customer's old name back, and can remove a mailing or shipping address that the first edit saved.
- **Untick Mail before Packages.** If you untick **Packages ship to this address** and type a shipping address, and only then untick **Mail goes to this address**, the choice under it switches to **Ship to the mailing address** and the shipping address you typed is not saved. Choose **Ship to another address** again before saving, or untick Mail first.
- Still open from v0.438.0: **Stop Safely** can be pushed off the screen in a console window narrower than about 780 pixels; **Choose machine...** on a ticket answers *No such machine.*; and an update can restart the console during a long Data Recovery job (press **Not now (1 hour)** on the countdown).
